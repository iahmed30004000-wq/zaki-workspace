Branch `feat/phone-chrome`. Phone only (below `md`) and only where the drawer exists (company switch `navV2`). The computer, the rail and the old map (`navV2` OFF: side menu, top bar, bottom bar) look exactly as before. No schema change, no migration, no new switch, no new API.

The computer (and the chat rail) keep the full dock. One query key serves all copies, so the server is asked once.

  - The dead phone cap in `switch-fx/switch-fx.css` (overridden by the inline sizes of `dimVars`, which the drag maths also read) is removed instead of being made to lie.
- The quick-chat round bubble is not drawn on a phone with the new map (`max-md:hidden`); from `md` up it is where it was.
- ONE assistant button: the compass «المرشد» (owner only: `siteGuide && ownerAssistant && isOwner`) does not float over a phone's page. On a phone the drawer's foot has the row «المرشد» (with a one-line hint) that opens the guide's panel through the window event `GUIDE_OPEN_EVENT` (`src/lib/nav/shell-v2.ts`). The class list is pinned by `tests/ui-feedback.test.ts` (not in this package's paths) so it is unchanged. The S5.2 `action` («افتح») still works (`tests/chat-forward.test.ts` green).
