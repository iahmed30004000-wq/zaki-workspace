# C3w.1 — Chat wiring, server side: the leftovers C1, C3 and C4 recorded

No schema, no migration, no new switch, no new string, nothing new on screen. It closes, on the server, the ⚠️ items that the merged packages left in files of other packages. The client halves of three of them are listed under «Not done here».

## Definition of Done
- What must work (each item was done with its failing test first):
  1. **`silent` leaves through the ONE presenter** (C3c.2). `MessageRow.silent?` and `dto.silent = true` in `presentMessage`: the messages window and the sync feed carry `silent: true` for a silent message and no field for a loud one.
  2. **The header and the list row carry what the screens read** (C3b.1, C3b.3, C3c.2, C3c.3, C3c.4). `ConversationHeaderDto` (through `ConversationDto`) gets `chatFormatting`, `chatAlbums`, `silentSend` (each the company's switch, ON by default) and `scheduled` (the person's OWN count of waiting scheduled messages here; ABSENT when the switch is off or the person may not write: the composer asks no list then). `ChatRowDto.postingPolicy` is filled for a topic row, so `rowChannelWord` no longer draws a channel for an announcements topic that a manager opened to everybody.
  3. **The personal mute stops the bell and the push** (C3a.1). `notifyMessageToAudience` drops every person whose `ConversationMember.mutedUntil` is in the future, before any row or push is made. DECISION (the spec names no exception): a mention and «@الكل» are muted too, «كتم» is كتم; the mention still counts in the list and among the person's unread mentions (they come from the message rows). Easy to change: one filter in `notify.ts` (`mutedAmong`).
  4. **Stripping, then cutting** (C3b.1). `messages.ts` passes the WHOLE body to `notify.ts` (and the edit passes the whole body to `rewriteMessagePreviews`); `previewText` strips the markers and then cuts at 140, so a bold run is not cut inside its markers and a link keeps its label. A reply quote (`presentMessage`, when the viewer carries `formatting: true`) and the header's pinned bar (`previewOf(…, { format })`) show the words, not the markers; `search-embeddings.ts` strips before filtering.
  5. **`lastMessageAt`** (C1.1 / C1.8). The assistant's answer and the ticket «✅ انحلّت» reply call `moveLastMessageAt` inside their transaction. (`forwardMessage` and every system line already did, since C1.8; the door's card writer too.)
  6. **The saved chat (a self key)** (C3a.3). `realtime/readers.ts` builds the same facts as `loadConversationFacts` for a self-DM, so the person's other tabs and phone get the frame (and nobody gains a reader: the same cells as the DM row of the matrix); the calls door refuses a call in a self key (`canStartCall(…, { selfDm })`, `calls.e.cannot_start`); search and the owner's oversight list title a self key from the dictionary (`isSelfDmKey`, `SAVED_TITLE_KEY`).
  7. **Pins can be dragged** (C3a.1). `scopeSchema` accepts `pins`; `PUT /api/chat/order` with that scope goes to `savePinsOrder` (`read-state.ts`, the same advisory lock as a pin): only the person's OWN pins are kept, in the order sent, the pins not sent follow. It never goes through `saveOrder` (which would have treated `pins` as a private-chat list and dropped every topic).
  8. **The C1.2 sync gaps** (C1.2, C1.3, C3a.1, C1.8). Deleting an empty topic writes an event that names the conversation (the space-only event stays: it wakes the other tabs). `emitPersonGone` (`moderation.ts`, called by the one line in `flipStatus` of `accounts.ts`) names every conversation a suspended or offboarded person had (a row of their own; every open topic of their spaces) BEFORE the rows and spaces are taken away, plus ONE event for the person alone. The sync feed now counts a conversation that a `membership.changed` event about THE PERSON themselves named as «known» (a person removed from a space no longer holds the space row that used to prove it). `forgetTypingFacts` is called on a removal from a topic (`removeMember`, `leaveTopic`) and on a removal or role change in a space (`changeWorkspaceMembers`).
