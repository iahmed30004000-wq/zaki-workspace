## Deviations from the plan text, and why
- **`router.refresh()` instead of `invalidateQueries` for the board's own data.** The plan says «TanStack mutation + `invalidateQueries`». The three actions ARE TanStack mutations and still invalidate `["board-stages", id]` (the real query the board has), but the cards and columns are server props: a second data door that rebuilds the cards (steps, fields, rewards, timers, pins) would duplicate a privacy-sensitive builder, and five older tests pin the board page's source for exactly those strings (`fieldCellsFor(`, `myRunningTaskId(actor)`, `lens.rewards && listBadgeStatus`, ...). `router.refresh()` is the way the task page already refreshes itself; the board keeps its state and takes the server's answer. If the owner wants a pure query, the data door is one function away.
- **The board tab embeds the board page itself** (`project-page.tsx` calls `BoardPage` and dresses its element), so the cards, the field chips and the visibility rule are the board page's, not a copy.
- **The task's trail asks `GET /boards/<id>/trail`**: `src/app/(app)/tasks/[id]/page.tsx` is not this package's file, so the task asks once by its board (names only; `show` is false while `navV2` is off; 404 for a board the person may not open). The route lives under `boards/[id]/` because `src/app/api/` is not in this package's paths. If the integrator prefers it, `crumbs={taskTrail(...)}` passed by the tasks page replaces the request (the prop already exists) and the route can go.
