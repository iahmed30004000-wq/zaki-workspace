# C3d — Info-panel tabs, the list's search and the in-chat search (no schema, no new switch)

## Definition of Done
- What must work:
  1. **`GET /api/chat/conversations/[id]/media?kind=IMAGE|VIDEO|FILE|AUDIO|LINK|MEDIA&before=&limit=60`** (new route, `src/server/chat/media.ts`). After the same reading rule as opening the conversation (`canRead`; always «not found» for what is not mine; a guest has topics only): the attachments of NON-deleted messages, newest first, in pages (`before` = the last id of the page before, a foreign or unknown id is 404; `limit` 1 to 100, default 60). **Never the file of a deleted message — the owner too** (the attachment route serves him the original; this list is not a way to it), never a system line, an upload no message claimed, a file the library deleted, or another conversation's. `MEDIA` is the pictures and the videos together (what the viewer steps through). `LINK` is the messages with a link card (`previewId`, status OK, a text message), and exists only while the two link-preview switches are on (the same ones that decide whether the card is drawn at all). `?counts=1` answers one number per kind by the same rule (so a tab with nothing in it is not drawn). The door is a READ: no read row, no event — a reader in silent oversight lists without a trace.
  2. **`GET …/media/work`** — the tab «الشغل»: the tasks and tickets whose `sourceMessage.conversationId` is this conversation. Tasks by P0.2's rule (`loadWorkScope` + `taskVisibleWhere`: a private task is not even counted for a person it does not concern; archived tasks are left out; the `tasks.view` box is needed), tickets by the ticket door's own reader rule (`canReadTicket`: whoever raised or holds it, the department's people, the OWNER and ADMIN ranks; the `tickets.view` box is needed). A guest learns of neither (as on the message chips). At most 50 of each.
  3. **The info panel's tabs** «الوسائط · الملفات · الروابط · الصوتيات · الشغل · المثبّتة» (`InfoTabs`, drawn at the foot of `InfoPanel`, so the computer's column, the tablet's sheet and the phone's `/chat/[id]/info` all have them). **A tab is drawn only when it has data**: nothing known is no tab, counts of zero are no tab, a conversation with nothing draws nothing (no placeholder). «الوسائط» is a grid of tiles (a tap opens the viewer), «الملفات» rows with name, size, author, date and a download link on our own address, «الروابط» rows with title and site opened in a new tab with no referrer (only an `http(s)` address is ever a link), «الصوتيات» a player per recording that loads nothing until played, «الشغل» tasks (a done one marked, a link to the task) and tickets (their state; a tap opens the ticket's own window), «المثبّتة» the header's pinned messages. Every row has «اعرض بالمحادثة»: the pane scrolls to the message (the sheet closes first; the docked column stays), the phone's info screen goes to `/chat/<id>?m=<message>`. Lists are asked for only while their tab is the one shown, with «عرض المزيد». Arrow keys move between tabs the way a right-to-left row reads.
  4. **The media viewer's source** (C3b.3) is switched to the route: once the viewer is open it reads `GET …/media?kind=MEDIA` page by page (at most 16 pages) and joins what it brought with the loaded messages' media (`mergeViewerItems`: one list, oldest first, each picture once, the loaded copy wins; a picture of a message the screen knows was deleted is dropped at once), so the arrows reach pictures that were never loaded. A failure leaves the viewer exactly as it was. The pane now wraps its messages in `MediaViewerProvider` (it was the missing wiring of C3b.3).
  5. **The list's search**: ONE request `GET /api/search?scope=chat&q=` (extends the existing route; backward compatible) answering `{ chats, people, messages }`: **chats** = topics by title (the existing `searchChat` pool and reading rule), the caller's OWN private chats by the other person's name (found with the arabic folding; a DM of two other people is never a result; a guest has none) and the spaces the person can open by name; **people** = the space's people, by the directory rule (a guest, and a person without `directory.view`, get `{ id, name }` only; the picture and the job title only with `directory.view`; each row carries `dmId`, the private chat already open with that person, when there is one); **messages** = snippet, chat, date, through `searchChat` unchanged (never a snippet of a conversation the caller cannot read, never a deleted message or a system line, the formatting markers stripped, Arabic folded). The list draws it as a panel over the rows (`ListSearchPanel`, in `ListHeader` and in the phone's `PhoneListBar`), only while there is something to show; opening a result clears the field; a person without a private chat open is a button that opens one through the existing `POST /api/chat/dm`.
  6. **The in-chat search** (`conversation-search.tsx`, which the old screen also uses): new optional props `enhanced`, `people`, `onJump`. With `enhanced` (the new pane only): ↑ goes to the older hit and ↓ to the newer one (the keys in the field, or two buttons; Enter is ↑, Shift+Enter ↓; «n من total»), the panel stays open while walking, «من:» limits the hits to one person of the conversation, and a date input jumps to the first message of that day (the local midnight is sent as `since`). All of it through `GET /api/search?scope=chat&conversationId=&q=&from=&since=` (the old per-conversation route does not know them and is not touched). **Without `enhanced` the component is exactly as before** (its markup is pinned by a test and the old screen passes none of the new props).
  7. **Privacy-matrix rows** (`tests/db/privacy-matrix.test.ts`, 4 conversation kinds x 9 personas, plus the task and ticket tables): the media route (the door's cell; never the file of a deleted message for anybody; the silent eye leaves no member row and no event), the list's search (a message is found exactly where the table lets the person read it, in every section; the same through the in-chat door), and the work tab (a task is named only to a person who may read the conversation AND see the task; a guest to nobody; a ticket by the ticket rule). The guest-sees-nothing cell of the work tab is written as data (`WORK_GUEST_EXCEPT`), like the list's own DM exception.
- Tests (new, all green): `tests/db/chat-media-route.test.ts` (12), `tests/db/chat-list-search.test.ts` (12), the privacy-matrix rows (+10), `tests/chat-v2-info-model.test.ts` (+16: the tabs, the keys, the addresses, the in-chat search's rules, the list's search, the viewer's merge), `tests/chat-v2-info-render.test.ts` (+19: every tab, the old search unchanged, the new one, the results, the wiring).
- Edge cases that matter: an album's pictures keep their order and are never dropped across a page boundary (the cursor is the message's time and the attachment's id); a cursor of another conversation is 404; with the link-preview switches off the link tab, its count and its list are empty; a link row whose address is not `http(s)` shows its text and is never a link; a date that does not exist (31 February) is no jump; a date jump ignores the words, typing words leaves the date; a failed list search says so instead of showing stale results.

## The failing test, before the change
The new test files were written before the code they test and could only fail at import (`Cannot find module '@/app/api/chat/conversations/[id]/media/route'`, `'@/lib/chat/v2/info/info-tabs'`, …). The list's search test was then proved against the OLD route and search module (the two files stashed): 10 of its 12 tests failed (`scope=chat` was ignored and answered the palette's keys; no `from`, no `since`, no private chats, no `dmId`, no names-only rows). The media and work tests were proved the other way, by mutation: with the task-visibility filter taken out of the work rows, and the deleted-message filter taken out of the media rows, 8 tests of the new files and the matrix went red (the deleted file listed, the hidden task named); the code was put back. The first run of the media test had one wrong expectation of mine (a bad query is 422 in this app, not 400), corrected in the test.

## Decisions used (say if one should change)
- **The info panel's jump goes through a context** (`InfoJumpContext`), not a new prop of `InfoPanel`, because two other packages' files mount the panel (`info-host.tsx`, `phone/info-screen.tsx`). The pane provides it; outside a pane the tab goes to the address with `?m=`.
- **The in-chat search uses the search route**, not `…/conversations/[id]/search` (not this package's file); the old route stays as it is for the old screen.
- **The date jump and the person filter are off with the «البحث الشامل» switch** (they are part of the search).
- **A guest's «الشغل» tab never exists** (the task table says a guest may open a public task; the chat has never named tasks to a guest on the message chips either).
- **The list's search results are an overlay over the rows**, not a replacement: the rows still narrow by the typed words (C2's rule) and the panel appears only when the server found something.
- **Spaces are offered by name from every space the person can open**, not only the current one; the forum view of another space opens through `/chat/s/<id>` as always.
