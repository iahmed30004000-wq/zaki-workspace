## Independent review
There is no tool in this worker session to start a separate agent, so the review was the `code-review` skill (a forked, read-only pass that read the diff and ran nothing; its first run was attached to another checkout and answered with an empty result, the second, run on the committed branch, returned 9 findings). Each was judged here; the new tests for the real ones were written first (the history, the search note, the screens and the FLIP churn tests failed on the code as it was; the forum box, the bell and the list bar were covered by render tests written with the fix):
- **Real, fixed:** (1) the forum view's header has no notch padding while the frame's top bar is hidden on `/chat/s/<id>`: the view is drawn in a box that starts below the safe-area inset (the forum file is not this package's, so the box is the list column's). (2) The whiteboard page was classified as a conversation screen, so the frame's bars went and its header had no inset: it is now «another page» (nothing marks it, no swipe), so the frame keeps its bars there. (3) The FLIP row cap could never trigger (a window holds fewer rows than 40), so a folder switch or a search keystroke slid every surviving row: the rows that ENTER or LEAVE the drawn window are now counted too (more than 2 means a new list, nothing slides), and a test pins a folder switch, a search keystroke, a new message and a row that jumps from far below. (4) The swipe, the conversation header's arrow and the info screen's arrow pushed new history entries, so the hardware back bounced between two screens: «back» now pops the history when the screen before is the target (a small trail of addresses the shell keeps) and replaces the entry otherwise. (5) The info screen's «🔍 بحث» only navigated back: it now leaves a note (fresh for 8 s) that the conversation pane's provider reads once and opens its search from. (6) With the old menu the frame's top bar (bell, account menu) vanished from the phone's chat list with nothing in its place: the frame hands the bell (and, with the old menu, the account menu) to the list bar. (7) The slide's `--zk-slide-from` comment claimed a left-to-right behaviour nothing sets: the comment now says the app is right-to-left only and the variable is a hook. (9) The FLIP bookkeeping re-attached every row's ref on every scroll render: the element of a row is now found only for the rows that moved.
- **Answered without a change:** (8) the `:has()` rule that gives the bottom padding back is coupled to the frame's shape and to browsers with `:has()`. The frame's column class strings are pinned by N1's tests (`people-dock`, `shell-render`), so a class or a prop on that column was not available to this package; a context flag would have meant re-rendering the frame on every chat screen change. Recorded under «Not done here» with the browser support and the pair a change must keep; the combination test pins the rule and the `#zk-main` it finds.
