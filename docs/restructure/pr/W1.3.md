# W1.3 — A normalized stage on board columns

Branch `feat/work-stage` (from `origin/main`). Switch: `workStages`, **OFF by default**. Schema change: ONE additive column (own migration folder) and its data move (ANOTHER folder).

## Definition of Done
- What must work:
  - `BoardColumn.stage TEXT NOT NULL DEFAULT 'DOING'` (`TODO | DOING | REVIEW | DONE`), migration `20261123102100_board_column_stage` — the column only, no `UPDATE`.
  - The data move is a SEPARATE folder, `20261123102101_board_column_stage_backfill`, with the plan's two statements, each with a `WHERE`:
    (1) `done = true` → `DONE`; (2) a board's first column (smallest `position`; ties: the smallest `id`) that is not done → `TODO`.
    Both only look at columns still at the default `DOING`, so they are safe to repeat and never touch a column a person already set.
  - A space manager (the owner, a space ADMIN, an org ADMIN who is in the space) chooses the stage: `PATCH /api/boards/[id]/columns/[columnId]` with `stage`
    (and `POST .../columns` with `stage`). A plain member can still rename / recolour / flag «منتهي», but a body that carries `stage` is refused with 403
    `column.stage_manager_only` and nothing is saved. An unknown stage is 422 (zod enum, `src/lib/work/stage.ts`).
  - New boards start with stages: `DEFAULT_BOARD_COLUMNS` = TODO, TODO, DOING, DOING, DONE (the done column is DONE). It is the one list used by
    `POST /api/boards` and by the inbox / instant board (`instant-work.ts` spreads the same entries, so it needed no edit).
  - `done` keeps its meaning: the flag and the stage are independent in both directions. `columnLabel()` still shows each board's OWN column name.
  - The board screen shows a «المرحلة» select in each column header, only to a person who can edit AND is a space manager AND while `workStages` is on
    (it asks `GET /api/boards/[id]/columns`, which answers the columns with their stage, `stagesOn` and `canSetStage`).
- Switch OFF (as merged): the board looks exactly as before; the column exists either way and the server accepts a manager's stage (only the UI choice is gated, as asked).
- Tests: `tests/db/board-column-stage.test.ts` (new, 24 tests) and the `workStages` test in `tests/features.test.ts`. Must stay green: `enums`, `arabic-ui` (unit and db),
  `guest-workspaces`, `teams-scoping`, `instant-work`, `work-inbox-project`, `migrations-lint`, `no-hardcoded-colors`.
- Edge cases that matter: ties on position; a done first column stays DONE (never TODO); the first column is picked per board; a second run changes nothing;
  a stage a person chose (anything but the default) survives a re-run; a body with both a rename and a stage from a plain member saves neither.
- Blockers: CI red · an old test red · a secret exposed · a destructive migration (none) · a feature removed instead of marked (none).
