# S5.3 — Folders from inside the chat, one topic pickable (switch `chatFolders`, existing; no new switch, no schema, no migration)

## Definition of Done
- What must work: (1) **«+» at the END of the folder strip** (phone strip and desktop column) opens ONE small sheet (`folder-sheet.tsx`): a name (12), an emoji, the chats picked on ONE screen with a search box, and ONE «حفظ». Nothing is written while the person ticks: the draft lives in the sheet and «حفظ» is ONE `PUT /api/me/chat-prefs` with the company's whole list (before: «مجلد جديد» was written, then retyped, then every tick was a write of its own). «حفظ» is off until there is a name. (2) **Long press (touch) or right click / the menu key (computer) on one of the person's OWN tabs** opens a little menu under the tab: «تعديل المجلد» (the same sheet, filled) and «حذف المجلد» (a confirmation first; the chats are not touched). The built-in tabs have no menu. (3) **«أضف لمجلد» in a chat's row menu**: one entry per folder (a tick where the chat already is: choosing it again takes it out; a folder at 100 chats is off for a new chat) and «مجلد جديد…» (the sheet with this chat already picked). One choice is one save with a toast. (4) **ONE TOPIC of a space can be added to a folder.** The topic id is stored in `include.conversationIds` (the schema already took it). The picker and the folder view work on the topics of the person's CURRENT space: with `chatOneList` OFF (production) the list already holds the topics of the space (`scope: "space"`); with it ON the list holds one row per space and none for a topic, so the topics of the current space (the space the shell says the person is in) come from the space's own view `GET /api/chat/spaces/<id>/topics` (the door the forum view reads). Only topics a folder lists by hand are added to a folder's rows (a folder that takes «المساحات» does not fill with every topic). (5) **Privacy:** a folder only keeps or drops the rows it is handed, and the picker, the badges and the folder view are handed only rows the list door or the space's view gave the person (the policy of `canRead`). A topic the person can no longer read is in neither: nothing is drawn for it, nothing names it (the editor only COUNTS «اختيارات مش ظاهرة إلك هلأ»). The id may stay in the folder, inert. (6) **ONE editor body** (`folder-form.tsx`, `FolderForm`) is drawn by the sheet AND by the settings page «المجلدات» (`ChatFoldersSettings` keeps its export; the settings page also shows the rules, whole spaces and exclusions; its «مجلد جديد» now opens the same sheet). (7) Max 10 folders per company stays (the «+» and «مجلد جديد…» are off at ten). Gate: the existing `chatFolders` switch (the prefs say `foldersOn`): off, there is no «+», no tab menu, no row entry.
