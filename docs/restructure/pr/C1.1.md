# C1.1 — `lastMessageAt` and the message cursor index

## Definition of Done
- What must work: (1) `Conversation.lastMessageAt` (nullable `TIMESTAMP(3)`, index `("orgId","lastMessageAt")`) exists; (2) it is written inside the `sendMessage`
  transaction, never moves backwards, and a retry with the same `clientId` does not touch it; (3) when the NEWEST message of a conversation is deleted (by the author or a
  moderator) it falls back, in the same transaction, to the newest message that is still there (NULL when none is) and deleting does not change `updatedAt` (the list
  order); (4) the data move fills the rows that are still NULL from the newest NOT deleted message, leaves empty conversations NULL, never overwrites a value the app wrote,
  and a second run changes nothing; (5) `ChatMessage ("conversationId","createdAt","id")` exists for the F0.8 `(createdAt, id)` cursor; (6) three migrations in three folders;
  `prisma migrate diff` against the schema is empty.
- Tests: `tests/db/chat-last-message-at.test.ts` (14).
- Edge cases that matter: a deleted message earlier in the thread is skipped when falling back; a system line counts as a message (same as the data move); a late older send
  never overwrites a newer value; a message sent while another is being deleted is never overwritten by the delete (the write only lands if the column is unchanged).
- Blockers: CI red · an old test red · a secret exposed · a destructive migration (none: the linter is clean, nothing is in `ALLOWED_DESTRUCTIVE.txt`).

## What changed
- `prisma/schema.prisma`: `Conversation.lastMessageAt DateTime?`, `@@index([orgId, lastMessageAt])`, `ChatMessage @@index([conversationId, createdAt, id])`.
- `prisma/migrations/20261119100000_conversation_last_message_at/` — the column and its index (additive; born NULL).
- `prisma/migrations/20261119100100_conversation_last_message_at_backfill/` — the data move, alone in its folder: one `UPDATE … FROM (max("createdAt") … WHERE "deletedAt" IS NULL …) WHERE … AND c."lastMessageAt" IS NULL`.
- `prisma/migrations/20261119100200_chat_message_cursor_index/` — the message index.
- `src/server/chat/messages.ts`: ONLY the send transaction (a guarded `updateMany`, one more statement) and `deleteMessage` (new private `recomputeLastMessageAt`).
- `src/server/chat/moderation.ts` and `src/server/chat/purge.ts`: NOT changed on purpose. Moderation (mute, the log) never deletes a message; the owner's purge deletes the whole conversation (its messages
  go with it by cascade), so there is no "newest message deleted, conversation stays" case in either file.
