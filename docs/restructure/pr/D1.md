> D1.1, D1.2 and D1.3 are ONE pull request here (they were built branch on branch and none of them changes a screen's behaviour). D1.4 (the credits) is the CREDITS.md line and the in-house wallpapers; the guide's «الاعتمادات» article is not written yet.

## Definition of Done
- What must work: (1) two new themes plugged into the EXISTING theme engine (registry, palette, FX colours, the decoration table) — «سماء» (light) and «ليل أزرق»
  (dark), selectable beside the four old ones, which are untouched and stay selectable; (2) nine chat tokens in every theme (`bubble-out`, `bubble-out-fg`,
  `bubble-in`, `bubble-in-fg`, `chat-wallpaper`, `chat-pattern`, `selected-row`, `selected-row-fg`, `badge-muted`), with values for the four old themes too, so
  every theme renders the chat; (3) the contrast gate learns the chat pairs (own bubble, incoming bubble, selected row, the muted badge) and every one of the six
  palettes passes it; (4) the six wallpapers drawn in-house (`public/brand/wallpapers/`), credited as our own work; (5) the flat themes wear no decoration in the
  four places where decoration was allowed (plain identity): a `PLAIN` voice whose rules draw nothing; (6) the switch `themeV2Default` (OFF) and `systemTheme()`:
  until it is on a person who never chose a theme gets «ليل» / «نهار» as before; with it on, «ليل أزرق» / «سماء» by the device. `DEFAULT_THEME` does not change.
- Tests: `tests/design-v2-themes.test.ts` (9) and the updated pins of the theme tests (six themes, six radio cards, the token list, the plain voice); must stay green: all
  the theme, manifest and decoration tests, the whole suite.
- Edge cases that matter: nobody who chose a theme is moved; the old themes' palettes and the pwa-manifest colours are unchanged.
- Blockers: CI red · an old test red · a secret exposed · a destructive migration (none).
