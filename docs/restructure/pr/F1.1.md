# F1.1 — One read per request: `cache()`, settings once, one Prisma client, jobs in the worker

## Definition of Done
- What must work: (1) the signed-in person, their membership, their space and the company's name and settings are each read ONCE per server render, however many layouts, pages and `isFeatureOn` calls ask; the `(app)` layout's independent reads run together (target at most 3 round trips); (2) NOTHING outlives a render: a session revoked, a rank changed, a seat suspended or a switch flipped between two requests is seen by the second one; (3) one Prisma client (one pool) per process in production too, `connection_limit` documented in `.env.example` and the README table; (4) the scheduler can run in the compose `worker` service behind `JOBS_IN_WORKER=1` with the same advisory lock, the variable read through `src/server/env.ts` (zod) and documented; the DEFAULT IS UNCHANGED (the app keeps scheduling).
- Tests: `tests/db/layout-calls.test.ts` (7, counted Prisma calls and round trips), `tests/request-cache.test.ts` (22, no database), `tests/repo-hygiene.test.ts` (its worker check now names the new entry). Must stay green: `tests/jobs-scheduler.test.ts`, `tests/env.test.ts`, `tests/db/shell-layout.test.ts`, `tests/db/features.test.ts`, `tests/db/auth-login.test.ts`.
- Edge cases that matter: `requireActor` keeps its order (the person and the onboarding gate first, THEN the membership); `requireActor({})` and `requireActor()` share one read (the key is the person's id, never an `opts` object); two people or two companies in one render never share an answer; an unset, blank, `0` or `false` `JOBS_IN_WORKER` changes nothing; a typo stops the boot with the variable's name.
- Blockers: CI red · an old test red · a secret exposed · a destructive migration (none, no schema change).

## The failing test, before the change
`tests/db/layout-calls.test.ts` run against the unchanged code (same harness, a request scope standing in for Next's): 4 of 7 failed. Counted, what ONE render of the `(app)` layout asked the database:

| | Prisma calls | round trips |
|---|---|---|
| before | 8 (`User.findUnique` x3, `OrganizationMember.findFirst`, `Organization.findUnique`, `Workspace.findMany`, `WorkspaceMember.findMany`, `OrganizationMember.count`) | 7 |

## What changed
**Commit group 1 — `perf/request-cache` (F1.1, F1.2, C1.9)**
- `src/server/env.ts`: `perRequest(fn)` = React's `cache()` where a render has a scope, the plain function everywhere else. It lives here because tests mock `@/server/db` and `@/server/auth` and this file is never mocked.
- `src/server/auth.ts`: `currentUser` and `pageUser` wrapped. `src/server/policy/actor.ts`: the membership read is `actorOf(userId)`, wrapped; `requireActor` calls `requireUser(opts)` and then `actorOf`. `src/app/(app)/_access.tsx`: `pageActor` wrapped. `src/server/services/current-space.ts`: the spaces read (`spacesFor`, three string keys) and the current space (`spaceFor`, the cookie value is part of the key) wrapped; `spacesOf` and `keepInSpace` share the read. `src/server/services/features.ts`: `orgSummaryOf(orgId)` (name and settings, one read) is what every `isFeatureOn`, `actorFeatureOn`, `isEconomyOn`, `listFeatures` reads; C1.2 reuses it.
- `src/app/(app)/layout.tsx`: the company, the person's picture and menu order, the space and the supervisor flag are read with `Promise.all`; the company comes from `orgSummaryOf`.

**Commit group 2 — `perf/prisma-one-client` (F1.8)**
- `src/server/db.ts`: the client is pinned to `globalThis` in every environment. `.env.example` and the README row of `DATABASE_URL` document `connection_limit` and `pool_timeout` (per process; the worker is a second process).

**Commit group 3 — `feat/worker-jobs` (F1.9, D-F1)**
- `src/server/env.ts`: `JOBS_IN_WORKER` (zod: `1`/`true` on, empty/`0`/`false` off, anything else stops the boot).
- `src/server/jobs/scheduler.ts`: `jobsRunHere(role, flag)`, `startJobRunner(role = "web")` (the web process schedules unless the worker has the jobs; the worker only when it has them), and `runJobsWorker()`, the worker entry: validates the environment (`DATABASE_URL` and `AUTH_SECRET` are required; `ENCRYPTION_KEY` is optional, so a missing one only logs `boot.encryption_key_missing`, and then the backup job refuses to run), starts the scheduler, heartbeat every minute. The scheduler reads the flag with `jobsInWorker()` (this one variable only), never through the full `env()`. `src/instrumentation.ts` logs `boot.jobs_in_worker` when the app leaves the jobs to the worker.
- `docker-compose.yml`: the `worker` service runs `runJobsWorker` through tsx (the image already has tsx, `src` and `tsconfig.json`) and gets the app's environment (`AUTH_SECRET`, `ENCRYPTION_KEY`, `APP_URL`, Google, SMTP, embeddings, VAPID, `NODE_ENV`) beside `DATABASE_URL`; both services pass `JOBS_IN_WORKER`. README and `.env.example` document the variable with the warning and the fix.
- Proved in a terminal, not in production: `npx tsx -e "import('./src/server/jobs/scheduler').then(m => m.runJobsWorker())"` loads the whole job graph outside Next, logs `worker.start jobsInWorker:false jobsStarted:false` and idles with the flag off, and with `JOBS_IN_WORKER=1` logs `jobsStarted:true` and runs its first tick (against an unreachable address on purpose, so it logged `jobs.tick_failed`, never touching a real database).

No migration, no schema change.

## Not done here (recorded)
- `cache()` has no request scope inside a route handler or a server action in Next 14 (React sets it only while rendering), so the API routes (the chat fetches that call `isFeatureOn` seven times, finding 6) still read per call. This package fixes server-component renders. C1.2 needs another scope for routes (an `AsyncLocalStorage` set by a route wrapper, or passing the summary along); `perRequest` in `src/server/env.ts` is the one place to teach it.
- `worker/index.ts` (the old heartbeat) is left as it is: it is not in this package's paths, and `npm run worker` still runs it locally. The compose worker no longer uses it; a later package can delete it.
- The worker has no graceful shutdown: on a stop its tick in flight is cut off (the advisory lock goes with the connection, every job is idempotent) and, as the image runs it through `npx`, SIGTERM may not even reach it.
- The hourly realtime purge job still starts in the app (`src/server/realtime/purge.ts` is not the job scheduler).
- Noticed, not fixed: `visibleNavFor` (`src/server/services/nav-order.ts`) still reads the company's settings itself; `currentUser` and `requireActor` each read the company's settings inside their own queries (one join each), so «once per request» holds for `isFeatureOn` and the layout, not for those two joins.
- `docs/CODEMAP.md` is not regenerated here (the integrator regenerates it).
- Not run: the full unit and database suites, `next build`, a real Next render (the request scope is stood in for by a test double with React's identity rule).
