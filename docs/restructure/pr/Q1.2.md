# Q1.2 — Product photos and feedback pictures (browser only)

> Owner's decisions (17/11): the product photos are uploaded later by the owner; this step is the BROWSER only — the installed Chrome app is a standalone
> window, so no Android bridge is built here (it could not be tried on this machine anyway).

## Definition of Done
- What must work: (1) a sheet's pictures are NOT library files: they are stored through the sheet's own door (`POST /api/knowledge/[id]/media`) as
  `StoredFile.purpose = "KNOWLEDGE"` (the library lists only `LIBRARY`), linked by a `CardAttachment` whose `role` is GALLERY (the product's photos) or
  FEEDBACK («آراء الزباين»), with a `meta` for feedback; (2) only the sheet's editors add; only pictures (JPEG, PNG, WebP — the bytes are sniffed, the client's
  type is ignored), at most 8 MB; the caps are 30 photos and 60 feedback items; (3) a FEEDBACK picture is somebody's private chat: the browser covers the name,
  the number and the profile picture BEFORE anything is sent (the original never leaves the phone) and the upload says `covered`; the server refuses it
  without; (4) a feedback item is offered to nobody but the editors until it has the customer's consent (an editor ticks it) AND an approver's approval
  (only with consent); withdrawing the consent withdraws the approval; (5) the bytes are served by the existing `/api/files/[id]/raw` only to people who may read
  the sheet (`assertMayReadFile` learns the KNOWLEDGE rule); a guest and an outsider get nothing; (6) on the sheet: the photos on top, swipeable; on any
  picture «انسخي الصورة» (the clipboard; a browser that cannot downloads instead and says so), «نزّليها», «شاركيها» (the share sheet); the feedback gallery with
  several selected → «نزّلي صورة صورة» / «اعمليهم صورة وحدة» → a preview → download, copy, share; (7) the collage is built IN THE BROWSER by a pure layout
  (`src/lib/cards/collage-layout.ts`): 2–9 pictures, never cropped, 2 columns for 2–4 and 3 for 5–9, the shortest column first, a white page, 12 px gaps, an optional
  caption, 1080 px wide (1440 with 3 columns), split when taller than 4096; (8) «ابعتيها بالمحادثة» (`POST /api/knowledge/[id]/media/[attId]/chat`) sends a COPY into a
  conversation as a chat attachment of its own, through the ordinary send path.
- Tests: `tests/collage-layout.test.ts` (8), `tests/db/knowledge-media.test.ts` (9); must stay green: the library, chat-files and knowledge tests, the whole suite.
- Edge cases that matter: a document renamed .png is refused (bytes); a feedback item without «covered» is refused; the library list never shows a KNOWLEDGE
  file; removing a picture ends access to its bytes.
- Blockers: CI red · an old test red · a secret exposed · a destructive migration (none).

## Independent review (read-only agent)
No way found to read or write what one should not on the server (the KNOWLEDGE rule goes through the sheet's own read rule, feedback needs consent and approval, no other door takes a KNOWLEDGE file, the bytes are sniffed). Real defects, each fixed (the server ones with a failing test first): the cover tool could keep the rectangles of the FIRST screenshot and paint them on a SECOND one chosen meanwhile (the tool is now tied to its file, and the button is hidden while it is open); a dictionary string named the formats in Latin letters (the Arabic guard would fail); the collage was copied as a JPEG, which the clipboard refuses (it is re-drawn as a PNG); two uploads at the same moment could pass the cap or share a position (one at a time per sheet and kind); a file stored whose link failed stayed forever (now removed); consent withdrawn during an approval could be lost (one state change at a time per picture); object URLs of the previews and of the original screenshot were not revoked. Recorded, not changed: the bytes of a removed picture stay on disk or Drive like library and chat files do; the gallery photos are not versioned by approval.
