# C4.2 — «الجلسات»: end one device (`UserSession`)

## Definition of Done
- What must work: (1) a new table `UserSession` (id, user, created, last seen, expires, user agent, the person's session version, revokedAt); the session cookie carries the row's id (`sid`); `currentUser()` refuses a cookie whose row is revoked or gone at the NEXT request (401 on an API route, a sign-in redirect on a page) while the person's other devices keep working and `User.tokenVersion` does not move. (2) A cookie issued BEFORE the deploy (no `sid`) keeps working until it expires: nobody is signed out by the deploy; it is migrated to a row when its owner opens the devices list. (3) Signing out ends the session row, so a COPY of the cookie stops working too (PHASE0-AUDIT R11). (4) `GET /api/me/sessions` (the person's live devices, this one marked) and `DELETE /api/me/sessions/[id]` («اطلع من هالجهاز»; the person's own session, or the OWNER's for somebody who was offboarded; anything else 404). (5) A «الجلسات المفتوحة» group on «إعداداتي» → «الأجهزة»; ending THIS device asks first and is a sign-out (queues and cache wiped like at any sign-out). (6) «اطلع من كل الأجهزة» keeps its rule: it deletes the caller's OWN `PushSubscription` and `AppDevice` rows in the same transaction, and now also marks every one of the person's rows ended. (7) The android app's login round trip and the call/ring stream keep working. (8) PHASE0-AUDIT R11 updated.
- Tests: `tests/db/user-sessions.test.ts` (28), `tests/session-id.test.ts` (11), `tests/middleware-session-id.test.ts` (3), `tests/session-devices-render.test.ts` (4), one new case in `tests/db/session-revocation-race.test.ts`. Must stay green: `tests/db/session-revocation-race.test.ts`, `onboarding`, `logout`, `settings-me`, `auth-login`, `auth-register`, `app-devices`, `pending-pages`, `legacy-routes`, `password-toctou`, `password-limiter`, `theme-login`, `login-lockout`, `accounts-*`, the middleware and settings-me unit tests.
- Edge cases that matter: a revoked session is never written to (last-seen) and never revived by an in-flight re-issue (the race test); a cookie that names someone else's session, or a session that is gone, is refused; a malformed `sid` in a signed token is REFUSED, never read as an old token; signing in again from the same browser replaces its session (one device in the list, not two); a password change keeps THIS device signed in under the same session and ends the others (they are no longer listed); an ended, expired or older-version session is not listed; only the person (or the owner, for an offboarded person with no active membership anywhere) lists or ends a session; the user agent is stored trimmed; no cookie, session id or user agent goes into a log or the audit row.
- Blockers: CI red · an old test red · a secret exposed · a destructive migration (none: one `CREATE TABLE`, one index, one foreign key).

## The failing test, before the change

## What changed
- **Schema** `prisma/schema.prisma` + `prisma/migrations/20261124101100_user_sessions/migration.sql` (additive; `migrate diff` against the base schema is exactly this SQL). `tokenVersion` on the row is the person's version it was issued under, so a bump (suspend, password reset, «اطلع من كل الأجهزة») leaves a row the list hides; `expiresAt` is the cookie's expiry so an expired session is not listed.
- **Token** `src/lib/session-token.ts`: optional claim `sid` (a cuid-shaped id; a malformed one makes the token invalid). The Edge middleware is UNCHANGED: it verifies the signature and expiry only (no database in the Edge runtime), lets a cookie with or without `sid` through, and the revocation is enforced by `currentUser()` for every page and API route.
- **Auth** `src/server/auth.ts`: `currentUser()` reads the session row IN PARALLEL with the user (one primary-key read, no extra round trip) and refuses a revoked / missing / foreign row; `CurrentUser.sid`; `startSession` gets `fresh` (a sign-in: new row, ends the row the browser's old cookie named), `adopt` (migration of an old cookie, used only by the list route), `userAgent`; a plain re-issue keeps the request's own session and NEVER revives a revoked one (the in-flight rule of AGENTS.md); an old cookie re-issued by the password change or the notice stays old-shaped.
- **Service** `src/server/services/sessions.ts` (imports no auth code): create / renew / revoke / list, `touchSession` (last-seen written at most once per five minutes per session by one conditional UPDATE: a fresh session costs no query at all), `trimUserAgent` (whitespace collapsed, control characters dropped, 200 characters), `mayManageSessionsOf` (self, or the OWNER of the company a person was OFFBOARDED from when that person has no active membership anywhere).
- **Routes** `src/app/api/auth/login` and `register/confirm` start a new session with the user agent; `src/app/api/auth/logout` ends the session the signed cookie names; `src/app/api/me/logout-everywhere` also marks every row ended (inside the same `$transaction` as the version bump and the deletes of the caller's own push and app rows); NEW `GET /api/me/sessions` and `DELETE /api/me/sessions/[id]` (audit row `auth.session_revoked` names the actor and the person, never the id or the agent).
- **Screen** `src/components/settings-me/devices-section.tsx` (the group «الجلسات المفتوحة», `sessionLabelOf`: the android app is recognised by its HTTP client), strings appended to `src/lib/i18n/ar.settings-me.json` (also `session.not_found`).
- **Docs** `docs/PHASE0-AUDIT.md` R11, `docs/restructure/README.md` (one row). `docs/CODEMAP.md` is the integrator's.

## Switches
None. The behaviour is on everywhere the moment the migration is applied: nothing visible changes for a person until they open «الأجهزة».

## Owner actions
- Deploy: the container applies the migration itself (`prisma migrate deploy`). Nobody is signed out.
- ⚠️ Cookies issued before the deploy cannot be ended one at a time (they have no session id): they live until they expire (at most `SESSION_TTL_HOURS`, 168 h) or the person presses «اطلع من كل الأجهزة». 🔧 If a stolen cookie is suspected, press «اطلع من كل الأجهزة» or reset the person's password (both end every old cookie at once).
- After the migration has been deployed, add its line to `prisma/migrations/RELEASED.txt` (`node scripts/lint-migrations.mjs --hash 20261124101100_user_sessions`).

## Not done here (recorded)
- **The Edge middleware does not check the session row.** The spec text said «the middleware refuses a revoked session»; the middleware runs in the Edge runtime where Prisma cannot run (pinned by `tests/middleware-onboarding.test.ts`). A revoked session passes the middleware for a PAGE and is refused one step later (`currentUser()` → the app layout sends it to the sign-in page); an API route answers 401 itself. A cheaper in-between would need a signed revocation hint in the cookie and is not worth a second source of truth.
- **No independent read-only reviewer could be spawned from this worker** (no agent tool in its toolset; the `code-review` skill it tried reviewed an unrelated checkout and its findings were discarded). The diff was reviewed by its author against the checklist of the plan only; the integrator's review is the independent one.
- **Old rows are never deleted.** An ended or expired row stays (a few hundred bytes per sign-in); a cleanup job (delete rows ended or expired more than N days ago) is a follow-up, not needed for correctness: the list is capped at 50 and filtered.
- **An old (pre-deploy) cookie that was migrated by opening the list still has its old copy alive** until it expires or the version moves: the copy carries no session id and cannot be ended alone. Same ⚠️ and 🔧 as above.
- **Ending a device does not disconnect that device's push browser or paired phone** (`PushSubscription`, `AppDevice` are not tied to a session row); only «اطلع من كل الأجهزة» disconnects them, as C4.1 decided. The phone's live line (`/api/device/stream`) authenticates with its own key, not the cookie, and is untouched by a revoked session (pinned by a source test).
- The owner's view of an offboarded person's sessions is the API only (`GET /api/me/sessions?user=<id>` and `DELETE /api/me/sessions/[id]`); no screen shows it (the members screens are other packages' files). Offboarding already bumps the person's version, so their cookies are refused anyway: this only lets the owner see and tidy the rows.
- The privacy section's link still says «شوف أجهزتك واطلع من كل الأجهزة» (an existing string, not rewritten; its file was not touched).
- Not run here: `npm run build` (no change to anything the build reads beyond the generated Prisma client), the full unit and database suites (the integrator's), the Android emulator workflow (`android-smoke.yml`: the sign-in answer and its cookie are byte-for-byte the shape they were, pinned by `tests/db/user-sessions.test.ts`).
