# F1.3 + F1.7 — A lighter shell: the calls library on demand, the helpers as chunks, calm decoration

> One branch, `perf/lazy-shell`, two steps of F1 (platform speed). No behaviour of any feature changes; only WHEN code is fetched, and one new stop on decoration under «وضع التوفير».

## Definition of Done
- What must work: (1) `livekit-client` and the call screen's picture code (`call-media.tsx`) are no longer part of any signed-in page: `CallProvider` loads them with `import()` when a call starts (`join`) or rings (`prefetch`); (2) the quick chat and the owner's guide are `next/dynamic` chunks (client only, nothing drawn while they load), fetched only by somebody who may have them; (3) a call still rings (the ring warms the connection) and still connects (`join` opens the room, the microphone, the camera for a video call); (4) F1.7: the two flat D1 themes draw and move nothing; the four old themes keep their decoration, paused when the tab is hidden (as before) and now OFF under «وضع التوفير».
- Tests: `tests/lazy-shell.test.ts` (13), `tests/decor-calm.test.ts` (15); must stay green: the theme, decoration, shell, call, economy, quick-chat, site-guide and people-dock tests (48 files, 750 tests run here).
- Edge cases that matter: a failed chunk load (offline) ends in the same «lost» state as a line that did not open, and the quiet rejoin tries again (the load is retried, a failed promise is not cached); the quick chat keeps its state while the person visits the chat page (it stays mounted, only its own `enabled` flips); a guest, or a company with the switch off, never fetches either chunk.
- Blockers: CI red · an old test red · a secret exposed · a destructive migration (none: no schema, no migration).

## The failing test, before the change
`tests/lazy-shell.test.ts`: importing the call keeper evaluated `livekit-client` (1 load, expected 0); the module walk from `src/app/(app)/layout.tsx` reached `livekit-client` and `quick-chat.tsx`; `app-shell.tsx` had no `next/dynamic`.
`tests/decor-calm.test.ts`: `DECOR_ECONOMY_ATTR`, `syncDecorEconomy` and the economy stop did not exist.

## Before / after (what the terminal can show)
The build's own route table does NOT show this change, and that is worth knowing: Next's «First Load JS» column counts the chunks of the page entry, but the chunks of the `(app)` layout's client components (the shell, the call keeper) arrive through the server-rendered tree and are not in that column. So the table says the same before and after, while the layout's chunk list changed:

| `next build` (same machine, same tree otherwise) | before (`main@920dbdb`) | after |
|---|---|---|
| table, `/` First Load JS | 279 kB | 279 kB (the column does not count the layout's client chunks) |
| table, `/my-work` | 279 kB | 278 kB |
| table, `/chat` | 325 kB | 325 kB |
| table, `/calls/[id]` (the call page itself carries LiveKit, as it must) | 386 kB | 396 kB (+10 kB: its chunk now also holds the picture code the keeper used to share) |
| client chunks of `/`'s whole tree (from `.next/server/app/(app)/page_client-reference-manifest.js` plus `app-build-manifest.json`; 125 client modules, 36 files) | 1954 kB raw, **544 kB gzip**, the LiveKit chunk (`5df4f2d8…`, 553 kB raw) in the list | 1380 kB raw, **398 kB gzip**, **no LiveKit chunk** |

So the first load of a signed-in page drops by about 146 kB gzip (574 kB raw) of script, and LiveKit is gone from it. The two numbers come from a throw-away script (not committed): union of the `chunks` of every client module in the page's client-reference manifest, plus the manifest's own entry chunks, gzip of each file. The tree is identical before/after except this branch.
What needs a browser's performance panel is NOT claimed: the time to interactive, the long task of parsing 553 kB less script, the 4x CPU throttle run — see Owner actions.

## What changed
- `src/components/calls/call-provider.tsx` — `import type` only from `livekit-client`; `loadCallLibs()` (one `Promise.all` of `import("livekit-client")` and `import("./call-media")`, cached, a failure can be retried); `join` asks for the pass and the library together, `prefetch` loads the library while the pass is fetched; every use of `Track`, `RoomEvent`, `Room`, the presets goes through the loaded module; `AudioOut`, `PersonPicture`, `mainPicture`, `nameOf` come from the loaded picture module. Nothing is drawn from the library before a room exists, and a room exists only after the load.
- `src/components/app-shell.tsx` — `QuickChat` and `SiteGuide` through `next/dynamic` (`ssr: false`, `loading: () => null`), mounted only for somebody who may have them. The `enabled` props keep the exact text that `tests/quick-chat.test.ts` and `tests/site-guide.test.ts` pin. Nothing else in the shell was touched (N1.2 rewrites it next).
- F1.7: `src/lib/themes/decor.ts` (`DECOR_ECONOMY_ATTR`, `syncDecorEconomy`, `holdDecorEconomy`, one economy stop in the stylesheet), the regenerated `src/components/theme/decor.css`, `src/components/theme/decor-visibility.tsx` (copies the screen's economy onto `<html>`; the last layer to unmount removes it).
- `tests/lazy-shell.test.ts`, `tests/decor-calm.test.ts`.

### F1.7 in particular
- «سماء» and «ليل أزرق»: verified, not changed. `PLAIN` rules make the four places `display: none`, they own no file, and no motion rule (drift, turn, zoom) selects them; `decor-calm` pins all of that.
- The old themes keep their pictures and their slow motion at the `full` level, paused when the tab is hidden (the existing `data-decor-hidden` rule, untouched).
- NEW under «وضع التوفير»: `[data-decor-economy]` hides every decoration layer and the two art-slot pictures, exactly as the level «off» does (`display: none !important`, so no picture is drawn and no animation runs). The company's switch reaches the page the way every economy timer already does: the shell tells `src/lib/economy.ts` while it renders.

## How a call still rings (the proof)
`tests/lazy-shell.test.ts` renders the real `CallProvider` and `CallRing` with the library mocked: importing and rendering them loads nothing (0 evaluations, 0 rooms); a `call.ring` event makes the ring ask the calls API, which makes the keeper load the library and call `prepareConnection(url, token)` on a room; `join("c1", false)` connects with the pass and opens the microphone, and `join("c2", true)` also opens the camera; the library is evaluated once.

## Not done here (recorded, with the owner of each)
- `nav-sort` (`@dnd-kit`) stays in the shell's first load. It is imported statically by `sidebar.tsx`, `bottom-nav.tsx` and `place-tabs.tsx` (and used only while «ترتيب» is on); making it lazy means editing those three files, which this package may not touch and which N1.2 rewrites. Recommended there: load the sort module with `next/dynamic` when `editing` becomes true.
- «مظهر المفتاح» (SwitchFx): its effect code (`fx-control`, `plain-scrub`, `reveal`) is ALREADY lazy (`theme-switch.tsx`, `use-theme-toggle.ts`); `SwitchFxProvider` is a context and must stay static. Pinned by a test, nothing to change.
- `PeopleDock` stays static: it is a row of the page at the first paint; a late row would push the page up (and `people-dock.tsx` is C1.3's).
- In economy mode the first frame of a visit still draws the decoration: the mark is written to `<html>` after hydration (a client effect). Writing `data-decor-economy` from the server needs the root layout (`src/app/layout.tsx`), which is not in this package.
- `docs/CODEMAP.md` is not committed (the integrator regenerates it).
- The pre-existing race that a «اطلع» pressed while a call is still connecting can be overtaken by that connection (the room is stored only after it connects) is older than this change (the library load is one more await in the same gap); noticed, not fixed here.
- The quick chat and the guide chunks load after hydration, so their buttons appear a moment later than before (both are `position: fixed`: nothing moves). `SiteGuide` listens for the assistant's «اتصل بالمساعد» event only once its chunk is in.

## Independent review
A read-only review of the diff (the `code-review` skill, run without tests) found: the economy mark could outlive every layer (fixed: `holdDecorEconomy`, last layer removes it, with a test); economy hid `.zk-decor` but not the two art-slot pictures that the level «off» hides (fixed, test updated); the `enabled` props repeat the outer condition (kept on purpose: two old tests pin that text; commented); the mark is written after hydration (recorded above); the race with leaving during a connection (recorded above, older than this change); the offline chunk failure ends in the quiet-rejoin path like a failed connection (checked: the rejoin effect and the visibility handler both re-enter `join`, which asks for the library again).
