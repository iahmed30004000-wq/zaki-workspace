# F0.R — What the independent review of F0 found

An independent reviewer read the nine F0 fixes and found holes in the listener's cursor and in the stream. Each one below was
reproduced (or proved by reading) and is closed here; what is left is listed with the step that owns it.

## Definition of Done
- What must work: (1) a replay that fails is retried (5 attempts, backing off), so a gap is never lost because live events had already
  moved the cursor; (2) a reconnect replays from 500 ids before the cursor (never below this process's boot cursor), so an event that
  committed after a higher one is still found, and nothing already delivered is delivered again; (3) an event that arrives live while a
  replay runs is not delivered a second time, whatever the replay's size; (4) a failed first connect of the LISTEN client is retried
  (the scheduler used to give up) and a half-made connection is closed; (5) a stream evicted or aborted while its replay runs leaves no
  heartbeat behind (it kept the person «online» and, through F0.5, swallowed their pushes until a restart); (6) a visibility report from a
  tab with no stream changes nothing; (7) coming back online while the tab is hidden does not reopen the stream; (8) a screen opened
  after an eviction still shows «الاتصال المباشر مفتوح بمكان تاني»; (9) the page re-reports its visibility at every ping (with
  `keepalive`), so a lost report is corrected within a beat; (10) the `before` anchor of a page of messages belongs to the conversation;
  (11) a waiting «read» is not sent while older messages (a search hit) are on screen; (12) the health check waits for the listener at
  most 2 s; (13) retries of a sent message are free of the send quota but have their own, wider limit (300 a minute).
- Tests: `tests/db/realtime-review-fixes.test.ts` (new: retry, late commit, long replay, ghost heartbeat, anchor),
  `tests/realtime-review-fixes.test.ts` (new: hub, hidden-and-online, eviction memory, ping report),
  `tests/realtime-listener-retry.test.ts` (new: a failed connect is retried, with a mocked client). Must stay green: the F0 tests, the
  whole suite.
- Edge cases that matter: the replay's `replaying` set is uncapped for the duration (the `recent` set stays capped at 2000); the overlap
  never goes below the boot cursor, so rows from before the boot are not re-sent; an old page that sends no tab id still reports for all
  of the person's streams.
- Blockers: CI red · an old test red · a secret exposed · a destructive migration (none).

## Not fixed here (recorded)
- If every subscriber of the page unmounts during a client-side navigation, `release()` forgets an eviction and the next stream may evict
  another tab again. The proper cure is one stream per browser (C1.3).
- Read and unread boundaries still compare `createdAt` alone (`home.ts`, `dm.ts`, `read-state.ts`): a message sharing the read message's
  instant with a larger id counts as read. C1.1 (`lastMessageAt` and the indexes) rewrites those readers.
- The LISTEN client has no keepalive or `end` handler, so a silently dead connection still reads `realtime: ok` until the next error.
- `/api/rt` registers the client before its per-client replay, so an event can arrive both live and replayed; the page does not dedupe by id.
