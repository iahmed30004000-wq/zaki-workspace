# F1.6 — A loading skeleton per place, shaped like its page

> One branch, `feat/place-skeletons`. Only `loading.tsx` files and one shared skeleton component. No page, no data, no schema, no migration, no switch changes.

## Definition of Done
- What must work: each of the 15 places below has its own `loading.tsx` that draws the SHAPE of its page (a list's rows, a desk's boxed sections, the departments' cards, a document's lines, a table, the production day, the watch room's player and side column), built from the one `Skeleton` primitive and the theme tokens: files, documents, knowledge, tickets, departments, goals, ideas, campaigns, crm, production, watch, time, checkins, cards, archive.
- The skeleton wears the SAME outer container classes as the page it stands for, so the width, the padding and the gap do not move when the page arrives (a test reads each page's source and fails if the two drift apart).
- It is a polite, busy status with ONE line for a screen reader, «جارٍ التحميل…»; every drawing is `aria-hidden`; no other word, no Latin letter or digit; logical properties only; no hex colour; no inline style.
- Calm: every block holds still under `prefers-reduced-motion` (the primitive's `motion-reduce:`) and in «وضع التوفير» (a block under `<html data-decor-economy>` has `animation: none`; verified that Tailwind emits `[data-decor-economy] .\[\[data-decor-economy\]_\&\]\:animate-none { animation: none }`).
- Server only and pure: no hook, no provider, no clock, no random number, no query. It never asks who is looking, so it promises nobody anything.
- Tests: `tests/place-skeletons.test.ts` (136). Must stay green: `ui-loading` (the whole app's own skeleton, C2.1's, untouched), the colour / Arabic / wording guards, the `ui-*` and `chat-v2-shell-render` tests (247 run here with the new file).
- Edge cases that matter: a loading file ALSO applies with `navV2` and `chatLayoutV2` OFF; so it is shaped by the PAGE (which both modes share) and never by a switch, and the loaded screen is not touched; `documents/loading.tsx` and `knowledge/loading.tsx`, `watch/loading.tsx`, `cards/loading.tsx` cover the only page of their folder (`[id]` / `[cardId]`); a refused person (guest, section off) sees the skeleton and then a short notice, which is the same as today with the old skeleton.
- Blockers: CI red · an old test red · a secret exposed · a destructive migration (none: no schema, no migration).

## The failing test, before the change
`tests/place-skeletons.test.ts` could not even load: `@/components/ui/skeletons` did not exist, and none of the 15 `loading.tsx` files existed (the guard «every place has its own loading file» is the list above).

## What changed
- `src/components/ui/skeletons.tsx` (new): `PLACE_FRAMES` (the outer classes of each page) and seven shapes, `ListSkeleton` (header, toolbar or the ideas' composer box, rows), `SectionsSkeleton`, `GridSkeleton`, `DocumentSkeleton`, `TableSkeleton`, `ScheduleSkeleton`, `RoomSkeleton`. Each part carries `data-skeleton-part`, each frame `data-skeleton-shape` (what the tests read; nothing styles on them).
- Fifteen one-line `src/app/(app)/<place>/loading.tsx`.
- `tests/place-skeletons.test.ts` (new).
- Registries, append only: one row in `docs/restructure/README.md`, one line in `docs/restructure/F1-platform-speed.md`.

## Switches
None. A `loading.tsx` cannot be switched off by a flag; it is shaped by the page, which both modes share.

## What the old screen looks like while loading (said plainly)
Before, these 15 places showed the whole app's placeholder (`src/app/(app)/loading.tsx`: a title bar, ONE usage tip, three cards, four rows). Now each shows its own page-shaped placeholder for EVERYBODY, `navV2` ON or OFF; the usage tip is not drawn there (it stays on every other place and on the chat). This is the point of F1.6 and it is only visible during the load; the loaded page, its markup and its data are untouched. C2.4 declined a `chat/[id]/loading.tsx` for the opposite reason (the chat's old screen had to look as before while loading); that is why `chat/loading.tsx` and `(app)/loading.tsx` are not touched here.

## Independent review
A read-only review of the diff (the code-review skill, no tests run) found, and this branch did: (1) the status line was the FIRST child of a `space-y-*` frame, so the first block sat one gap lower than the page's first element (fixed, test first: the line is now the last child, pinned for all 15); (2) the frame-drift guard was a bare substring match (now it must be the first element a `return` draws, with exactly the page's classes); (3) `ListSkeleton` ignored `toolbar` when `composer` was set and tied the header's button to it (three independent props now, tested); (4) the table was one shape for two different pages (now `lead="tabs"` for the customers, `lead="filters"` with a title, a filter bar and six columns for the time report, tested); (5) a tautological «every folder is listed» test (now it checks that every listed place is a real folder with a page under it).
Looked at and NOT changed: the status uses the same `role="status" aria-live="polite" aria-busy="true"` as the whole app's own skeleton (C2.1's), and a live region that is mounted with its text is not reliably announced by every screen reader, so «one line for a screen reader» is the markup's promise, not a measured announcement; `bg-surface` (toolbar, composer, day bar) next to `bg-surface-1` (boxes) follows what each page uses, they are tokens of the same theme; the skeleton's rows and columns are an approximation (a count, never the page's real data), so the height can still change when the real rows arrive, only the width, padding and gap are pinned; one shape per place is chosen in each `loading.tsx` and the test's table names the same choice again (a place that changes shape is a two-file edit).
