# C3a.2 — The person's own chat folders and chat preferences (`User.chatPrefs`, `chatFolders`, ON)

## Definition of Done
- What must work: (1) **Storage.** `User` gains ONE nullable JSON column `chatPrefs` (`prisma/migrations/20261123101100_user_chat_prefs`, additive, `migrate diff` empty, `RELEASED.txt` untouched). C4.1 and C3b.4 reuse it: no second prefs column. (2) **One zod schema** in `src/lib/chat/prefs.ts`: every field optional, its default in code (`resolveChatPrefs({})` is «all defaults»); `folders` keyed by company id (at most 10 per company, name 1 to 12 characters, an optional emoji that is not letters or digits, `include { dms?, spaces?, mentions?, conversationIds ≤ 100, spaceIds ≤ 50 }`, `exclude { muted?, read?, archived? }`, ids plain and distinct); `tabs.hidden` (the built-in tabs the person hid); `notifications` and `chat` (room for C4.1: a bounded map until it gives them fields); `voiceSpeed` (1 · 1.5 · 2, C3b.4). Writing is strict (`.strict()`, unknown keys refused), reading is forgiving (`readChatPrefs` drops what is damaged and keeps the rest). (3) **The door.** `GET/PUT /api/me/chat-prefs` (`withApi`, `requireActor`): the caller's OWN row only (no id in the address, a body that names a person is a 422); a PUT is a PATCH (a section named is replaced, the others stay, `null` puts one back to its default, the folders merge per company); the body is read with a 64 KB ceiling (`readTextLimited`) and a merge whose result would pass 64 KB is refused too; the merge runs under a row lock, so two devices saving different sections both stay; folders keyed by a company the person is not an ACTIVE member of are a 403 `chatprefs.not_your_company` and nothing is written; an empty result puts the column back to NULL. The answer is `{ prefs, orgId, foldersOn }`. (4) **Filtering is client-side**, a pure unit-tested `src/lib/chat/folders.ts` over the rows of the C1 list cache. A row is in a folder when ANY include rule matches and NO exclusion does; a folder that includes nothing shows nothing; a folder can only keep or drop the rows it is handed, so a chat the person can no longer read (not in the cache) shows nothing and is never named (the editor only COUNTS such picks). (5) **The tabs.** The built-in «الكل · غير مقروء · خاص · المساحات · ذكروني» are not stored; the person may hide any of them (never all: with nothing of their own «الكل» stays); their folders follow, then «الأرشيف» and «كل الشركة» as before. (6) **The editor** is a reusable controlled component (`FolderEditor`) plus a connected `ChatFoldersSettings` for C4.1's «المجلدات» page: create (at most 10, the 11th button is off and says why), rename (12 characters), emoji, include rules, chats by hand, whole spaces, exclusions, drag to reorder (the grip, or the keyboard), delete, and the checkboxes of the built-in tabs. (7) **The switch `chatFolders`** (default ON): off, the folders and tabs are not answered (`foldersOn: false`) and cannot be saved (404 `features.off`); the other sections of the prefs keep working, because they do not belong to this switch; what was stored stays. The old screen keeps its own folders and ordering.

## Independent review
There is no tool in this worker session to start a separate agent, so the review was the `code-review` skill (a forked, read-only reviewer that reads the staged diff and runs nothing). It gave 9 findings. Each was judged here.
- **Real, fixed (tests written and seen red first):** (1) the «not visible to you» banner and its clear button treated every pick as unavailable while the list was still loading or had failed, so one tap could erase a folder's picks — `FolderEditor` has `chatsLoaded` (the connected one passes it), the banner now says «اختيارات مش ظاهرة إلك هلأ» (a topic is not a row of the one list, so «not visible» is the accurate word) and shows nothing until the list has come; (2) every key typed in the name box fired a PUT under a row lock — the name is now saved on leaving the box or Enter; (3) the draft state of the connected editor could stay pinned over the server's data after two overlapping saves — the drafts are gone: `saveChatPrefs` shows the change in the cache at once, sends the requests one after another, lets an older answer never overwrite a newer change, and on a refusal marks the cache to be read again (4 unit tests with a stubbed `fetch`); (4) a delete for a company the person left was refused with the same 403 as a write, so hidden folders could eat the 64 KB budget with no way out — dropping a list (null or empty) is never refused; (5) `{org: []}` was stored and answered but read back as nothing — an empty list is now a delete in the merge; (6) a name may no longer carry bidi overrides or zero-width characters (the joiners of Persian and Arabic stay); (7) the service read the person's companies twice and with the switch off for nothing — once, and only when needed.
- **Judged, kept as built:** (a) the cache key is fixed (not per person): sign-out is `window.location.href = "/login"`, a full page load, so a client never outlives the person (the saved order of the list does the same); (b) a topic cannot be picked by hand in the one list (it is a chip of its space's row): the picker offers private chats and groups, topics are reached through «مساحات كاملة», and in the one-space list shape topics are rows and can be picked — written under Owner actions.
