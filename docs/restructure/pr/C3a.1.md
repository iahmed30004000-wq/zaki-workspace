(8) **The switch `chatPersonalState`** (default ON): off, the route answers 404, the list and the feed send none of it (an archived chat is in the list again), the menu draws no personal item and no «الأرشيف» tab; the data stays and comes back with the switch. So «كتم الإشعارات» mutes the row (grey pill, bell-off icon, and it keeps an archived chat archived) but does not yet stop a push or a bell notification. 🔧 A one-line filter in the audience of `notifyMessageToAudience` (people whose `mutedUntil` is in the future); it needs its own failing test.

## Independent review
There is no tool in this worker session to start a separate agent, so the review was the `code-review` skill (a forked, read-only reviewer that reads the diff and runs nothing). Its first run read another checkout (the scratch repository's own branch) and said so; the second and third were pointed at this worktree. The third gave 10 findings. Each was judged here.
- **Real, fixed (the first with its test written and seen red first):** (1) an archive that a message had already ended came back by itself when the chat was muted later (`archivedAt` is never cleared by a message, so a later mute made it stand again) — `setMyChatState` now clears a stale `archivedAt` when it sets a mute on a chat whose archive a newer message already ended (test: «an archive that a message already ended stays ended when the chat is muted LATER»); (2) the advisory lock was taken for a pin only — an un-pin racing a pin could be counted as still pinned and both could write a stale order — it is taken for every pin change; (3) a mute computed from a device clock that is behind the server's is a time already past on the server, so nothing was kept while the toast said «تم» — the screen now says it failed when the answer holds no `mutedUntil`; (4) the body was validated twice (the route and the service) — the service takes the parsed type; (5) an unused import and a stray blank line.
- **Judged, kept as built, and written above:** (a) a pin, archive or mute of an open topic the person never opened creates the row with the read mark at «now», as `markRead` does (the spec says «like markRead»): the topic's old history stops counting as unread for that person — the alternative is a whole topic's history in the sidebar number; (b) a topic archived for myself is not in the one list's «الأرشيف» tab (see Owner actions); (c) with the switch off and the list not yet in the cache (a deep link straight to a forum view) the personal items are drawn for a moment until the list arrives, and a click is answered 404 and said; (d) the switch is read inside the list's SQL several times: each is an uncorrelated one-row lookup by primary key that Postgres evaluates once per statement, and the alternative (a separate read) would break the pinned «the feed reads no settings» test; (e) `chatui.empty.archived` is drawn only if the archive folder is the active one with no rows (the tab goes away when the last archived chat leaves, and the folder falls back to «الكل»).
