# S5.7 — small Telegram parity on the new chat screen: «حذف عندي», swipe to reply, date jump, «رد بالاقتباس», row swipes (ADDITIVE migration `20261126110000_chat_parity_small`)

Everything lives on the `chatLayoutV2` screen only (the old chat screens are untouched). No new switch: each piece is behind the existing `chatLayoutV2` (the delete-for-me door and the quote answer 404 / ignore while it is off) and `chatPersonalState` (the row swipe buttons).

## Definition of Done
- What must work:
  1. **Schema (additive):** one nullable column `ChatMessage.replyQuote TEXT` and one new table `ChatMessageHidden (id, messageId, userId, createdAt; unique (messageId, userId); index userId; both foreign keys ON DELETE CASCADE)`. Nothing dropped, changed or backfilled. `node scripts/lint-migrations.mjs` is clean (108 migrations, 80 released); `prisma migrate diff` from the migrations to `schema.prisma` is empty (checked on a throw-away database); the folder is not in `RELEASED.txt` (added after the deploy). The quote uses a column and not a JSON field: `card` and `ackMeta` already mean other things, and a plain text column is the lightest thing that can be read by SQL and cut by the database.
  2. **(a) «حذف عندي»:** a hidden message leaves EVERY read path of that one person — the message page (`GET …/messages`, also the `around` window), the sync feed, the in-chat search (words, «من:», the date jump, picture-text), the chat search over a space, the media tabs and their counts (pictures, files, voice, links), the list's last line and unread/mention counts, the unread badge (`unreadTotal`, `unreadBySpace`) and the calendar of the date jump — and changes nothing for anybody else, nothing in the message (no tombstone, no edit mark, no audit line), nothing in the owner's archive or oversight, and nothing about who may delete for everybody. Door: `POST /api/chat/messages/[id]/hide` (404 for a message of a conversation the person cannot read, nothing written; idempotent), and `POST /api/chat/messages/delete` with `forMe: true` for the selection (each id reported on its own; the existing switch `chatMultiSelect` applies there). Any message the person can read, their own or somebody else's. Their other devices are told through the realtime line with `targetUserId` (ids only, the same shape as a personal pin) and the sync answer carries `hidden: [ids]` read from their own table. The menu has «حذف عندي» (with a one-line confirmation) beside the registry's «احذف»; the selection bar has the same button and a confirmation.
  3. **(b) swipe a message to reply (phone):** a finger drags the bubble from the start side toward the end (leftwards in the right-to-left page; mirrored in a left-to-right one); at 64 px the phone buzzes once (`navigator.vibrate`, feature-detected, never throws), at the release past it the reply starts through the same door a double click uses (the registry decides who may reply). It never fights: the vertical scroll (the first decided move must be mostly sideways, `touch-action: pan-y`), the swipe back (a touch that begins in the 24 px strip at the start edge is not ours), a link / button / player / field, the long press, selected text, the multi-select (off while selecting), a mouse or a pen. Reduced motion: no animated snap-back.
  4. **(c) date jump:** tapping the floating date chip (while it shows) opens a small month sheet in Levantine month names, Saturday-first weeks, Western digits; every day is closed except the days that hold a message the person can see; a day jumps to its first message with the history's own `jumpTo` (the window around it + the 2 s highlight). Doors (same route as the pages, `GET …/messages?days=YYYY-MM` → `{ days }`, `?onDate=YYYY-MM-DD` → `{ id | null }`): the days are cut in the company's own clock (`Organization.timezone`, the one «اليوم» counts in) or a valid zone the caller names (`tz`); a bad month / date / zone is a 422, a conversation the person cannot read is a 404, a hidden message's day is not offered to the person who hid it.
  5. **(d) «رد بالاقتباس»:** select words inside ONE message → a small «رد بالاقتباس» button over the selection starts an ordinary reply and keeps the piece; the reply bar shows the quoted piece (marked as a quote) in place of the whole message; the send carries `replyQuote`; the bubble's reply block shows the quote. The server keeps it only with `replyToId`, only while `chatLayoutV2` is on, cut to 280 characters (whole characters), spaces squashed, and ONLY when it really is a piece of the parent's words (as written or as drawn without the formatting markers): a made-up quote is dropped and the reply goes as an ordinary reply, so nobody can put words in another person's mouth. The DTO carries it as `replyTo.quote` beside the preview — only for a live original (a deleted parent, or a deleted reply, carries none, so the quote is never a way to read deleted words); it is plain text and React escapes it on both screens.
  6. **(e) row swipes (phone list):** on the phone's tall rows the row slides toward the start edge and shows «تثبيت · كتم · أرشفة» (the opposite word where the row already is pinned / muted / archived), through the very same personal door as the row menu (`PUT …/me`, switch `chatPersonalState`). Settles open past half or on a quick flick; one row open at a time; a tap on an open row only closes it; never the vertical scroll, never the swipe back's edge strip. A space row (a forum), the chat with myself and a company with the personal items off have nothing to swipe, and the computer's list is exactly what it was. A mute from a swipe is «للأبد» (the menu's presets are still the way to choose a time).
