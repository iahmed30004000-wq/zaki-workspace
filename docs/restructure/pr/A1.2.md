# A1.2 — the clear permissions sheet and «شو بيقدر يعمل؟»

Branch `feat/permissions-sheet`. No schema change, no migration, no new company switch (A1.2 changes how the existing boxes are SHOWN; A1.1's `permissionTemplates` is untouched).

## Definition of Done
- What must work:
  - The person's sheet is read by AREA in plain words: «المهام والمشاريع», «الدردشة والمكالمات», «الملفات», «الزبائن والأسعار», «التقارير واللوحات», «إدارة الناس والمساحات», «التكاملات» (and «مخزون التصنيع» for the stock ledger's three boxes, which belong to none of the seven). Each area is collapsed by default (a native `<details>`), shows how many of its boxes are on, and holds the grid's three columns «يشوف / يضيف ويعدّل / يحذف» for its sections and its single switches with one-line explanations. Every box is the same box as before with the same locks (a test compares the area view with `capabilityGroups` / `sectionGrid`).
  - «شو بيقدر يعمل؟»: a collapsed section above the areas listing every OFFERED permission with ✓/✗ and WHY — rank default · added by hand · removed by hand · the rank does not give it · needs «يشوف» first · «صلاحيات الأقسام» off · owner/partner · guest · owner-only · and «الشركة طفّت ميزة …» when the feature behind the permission is off. It is `explainCapabilities(member, settings)` (pure, in `capabilities.ts` next to `effectiveCapabilities`); its `held` IS `effectiveCapabilities`, the reasons only describe it.
  - The view may never promise what the server refuses: `tests/policy-capabilities.test.ts` compares it with `effectiveCapabilities` for EVERY rank (primary owner, partner, admin, lead, member, guest) × section grid on/off × ~120 stored shapes (each capability alone added, alone removed, all added, all removed, both, an unknown name); `usable` is never more than `held`.
  - `tests/db/capability-explain.test.ts` compares it with the real server on real rows: the roster's own `effectiveCapabilities`, `memberCan` for all 55 capabilities of six people (a partner with removed boxes, an admin, a lead, a member with extras and removals, a guest with stored extras), grid on and off; and the door of «ضبط التصعيد» (404 while `autoTickets` is off — the view says «الشركة طفّت ميزة»; 200 once on; 403 for a person without the box — the view says why).
  - Hidden only what is still wired to nothing: `announce.send` (Q1.6: who may mark «لازم ينقرأ») and `escalation.configure` (Q1.5: the door of «المشاكل تصير تذاكر») are CHECKED now, so they are in `WIRED_CAPABILITIES` and offered again («الدردشة والمكالمات» and «المهام والمشاريع»); `cash.view` and `penalties.view` stay hidden (named under «قريبًا»; the sheet draws them as text, never as a switch) until I1.3. `docs/PHASE0-AUDIT.md` R12 is updated.
  - `tasks.delete`: D-A1 is not answered, so the box only gets the hint «بيحتاج كمان يكون مدير المساحة» (under the tasks row and as the box's tooltip); the route's rule is unchanged.
  - «قائد الفرقة»: a picker in the teams dialog (`workspace-teams-button.tsx`) writes `Team.leadId` through the existing `PATCH /api/workspaces/[id]/teams/[teamId]` (a manager of the space only; the lead must be one of the team's people). One server change in `services/teams.ts`: the lead must also be an ACTIVE member of the company (`403 teams.lead_not_active`), so a suspended or offboarded person who still has a team row is not made the lead of «لوحة الفريق».
  - The rank hints (`members.rank_hint_*`) say what `RANK_DEFAULTS` gives: the lead «متل الموظف، وكمان بيشوف الأسعار وصفحة «التقارير»»; the admin lists accounts, integrations, spaces, customers, prices, directory, reports, announcements, escalation and the stock ledger without the cost; the member lists what he works in and says «بدون أسعار وبدون تقارير». `tests/members-rank-hints.test.ts` holds a small data table of each hint's claims and checks them against the rank defaults (every claim true, every switch the rank gives is said except everybody's own «لوحتي», a lead is exactly a member plus the prices and the reports).
  - Security rules unchanged: no check, route or rank rule was touched; the explain view fetches `/api/settings/features` (staff may already read it) and reads nothing else.
- Tests (all new files or additions): `tests/policy-capabilities.test.ts` (+22: the explain agreement and the reasons) · `tests/members-rank-hints.test.ts` (new, 25: the hints' data table, the areas, the explain view by area, what is drawn) · `tests/db/capability-explain.test.ts` (new, 6: the real server, the escalation door, the team lead).
- Edge cases that matter: a stored removal of a grid box is ignored while «صلاحيات الأقسام» is off (the reason says so); a stored add/edit/delete without its «يشوف» is shown as needing it; a person both given and refused a box is refused (as the server does); a removal of something the rank never gave changes nothing («الرتبة ما بتعطيه ياها»); the features start OFF for `mustRead` and `autoTickets`, so with the company's defaults an admin's «إعلانات للجميع» is held but not usable and the view says so; while the company's switches are loading the view draws no rows and claims nothing.
- Blockers: CI red · an old test red · a secret exposed · a destructive migration (none) · a feature removed instead of marked (none).
