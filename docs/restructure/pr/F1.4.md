# F1.4 — No reload in the space-edit button; a refresh only where a server page must draw again

## Definition of Done
- What must work: (1) editing a space's name or description no longer reloads the browser page (`window.location.reload()` is gone from `workspace-edit-button.tsx`): the company's spaces list (the switcher, client-fetched under the key `["orgs"]`) is asked again and the server-drawn page is drawn again in place with `router.refresh()`; (2) deleting a card from its own page no longer re-runs the server tree: the cards list is client-fetched (`["cards", spaceId, "live"]`, TanStack Query), so the list is invalidated instead; the person still lands on `/cards`; (3) every other `router.refresh()` in the files of this package stays, because each one draws a server-rendered page (props from a `page.tsx`) again — it is the only way those pages see the new data. No behaviour change.
- Tests: `tests/no-refresh.test.ts` (6, source text: no reload in the space-edit button, the `["orgs"]` invalidation and one soft refresh there, the card page invalidates `["cards"]`, still pushes to `/cards`, a per-file ceiling and a total ceiling on `router.refresh()` over the package's files and directories, no `location.reload()` anywhere in them). Must stay green: `tests/cards-page-render.test.ts`, `tests/no-hardcoded-colors.test.ts`.
- Edge cases that matter: the space page shows the name and description from the server, so the button keeps one `router.refresh()` (without it the old name stays on screen until the next navigation); the cards list keeps its `initialData` from the server for a first visit — on a return to `/cards` the query already in memory is marked stale and refetched when the list mounts.
- Blockers: CI red · an old test red · a secret exposed · a destructive migration (none: no schema, no migration).

## The failing test, before the change

## Which refreshes stay, and why (server-rendered pages: the data arrives as props from `page.tsx`, nothing client-fetched to invalidate)
- `manufacturing/` (`material-page`, `mfg-view`, `orders-view`, `recipes-view`): each keeps the server's props in local state and re-reads them from the props through `useEffect(() => setData(initial), [initial])`; the refresh is what delivers the new props.
- `team-development/` (notes, skills, plan, reviews, settings, catalogue, supervisor picker), `rewards/` (pin button, reward card), `knowledge/sheet-view.tsx`, `org-name-form.tsx` (the company's name is drawn by the server layout), `watch/watch-room.tsx` (the session's state), `approvals/` (detail, request form, form builder, archive button): server pages, no query.
- `documents/document-page.tsx` (undelete) and `documents/documents-view.tsx` (bring back): the list and the page are server props; the revision queries on the page are invalidated already where the data is client-fetched.
- `ideas-view.tsx` (status change, convert to a task): the list is local state fed by the server's answer; the refresh also re-draws the server-rendered tasks and counters. Not removed: no proof here that nothing else on screen depends on it.
- `workspace-edit-button.tsx`: the page title and description are server-drawn (see above).
