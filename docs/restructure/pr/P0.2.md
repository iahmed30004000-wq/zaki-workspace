# P0.2 — A task can be private («المعنيين بس»)

## Definition of Done
- What must work: a task has `visibility` (`SPACE` = the whole space, the default; `PARTICIPANTS` = «المعنيين بس»). A private
  task is read only by its creator, its assignees (the first and the people beside), their managers up the reporting line
  (depth 6), the managers of its space, and whoever holds silent oversight (`archive.view`). For everybody else it is 404
  on every door, absent from every list, not counted, no chip in the chat. A public task, and a guest, behave as before.
  The creator, a manager of the space, the assignee's manager or oversight change the choice (each change is a line in the
  task's log); a space manager can make all the open, assigned, public tasks of a space private in one click.
- Tests: `tests/db/task-visibility.test.ts` (new, 10 cases), `tests/task-visibility-guard.test.ts` (new, source text: every
  read of the Task table in `src/` goes through the rule or says why not), `tests/features.test.ts` (extended for the new
  switch), `tests/rewards-logic.test.ts` (the one new task writer is listed with its reason). Must stay green: the whole
  suite, `tests/db/teams-scoping.test.ts` above all.
- Edge cases that matter: the rule is ONE helper extended (`taskVisibleWhere` in `team-scope.ts`) — its 18 callers got it for
  free; raw SQL gets `taskVisibleSql`; a single row `canSeeTask`; `requireTaskAccess` and `requireTeamWork(…, task)` refuse
  with 404 (existence is private too). A partner (OWNER rank) without `archive.view` and without an ADMIN row in the space
  is NOT a space manager for this rule (P0.1). A task from the door, e-mail, n8n or the owner's assistant is public unless
  the sender says otherwise; a recurrence copies its template's choice.
- Blockers: CI red · an old test red · a secret exposed · a destructive migration (none: one column, one index).

## What changed
- Migration `20261116100000_task_visibility`: `Task.visibility TEXT NOT NULL DEFAULT 'SPACE'` + index
  `(workspaceId, visibility)` — additive, no backfill (D-P3: every existing task stays as it is). `prisma migrate diff`: none.
- `team-scope.ts`: `WorkScope` gains `userId`, `managedSpaces`, `reportIds`, `oversightSpaces`; `taskVisibleWhere` adds the
  participants rule; new `taskParticipantWhere`, `taskParticipantFilter(userId)`, `canSeeTask`, `canSeeTaskParticipants`,
  `taskVisibleSql`; new `reporting-line.ts` (the walk down the line).
- `auth.ts`: `requireTaskAccess` and `requireTeamWork(…, task)` refuse a private task (one `assertTaskParticipant`); the four
  routes that fetched a task by hand (comments, comment, complete, move) pass it.
- Readers: boards page and route, project page counts, timeline, roster counts, profile counts, task list, field export now
  filter; 60+ system, own-task and owner-level readers carry `// task-visibility: <reason>` (list in the guard test).
- Writers: `createTask` / `updateTask` take `visibility`; who may change it is `mayChangeVisibility`; the log line
  `task.visibility_changed`; the routes accept the field; recurrences copy it.
- Chat: the «صارت مهمة» chip of a private task is shown only to people it concerns.
- UI: a lock on rows, «مين بيشوفها؟» on the task page (with ⚠️ + 🔧 when a task that somebody holds is for the whole space),
  and «خلّي المهام المسندة المفتوحة خاصة» on the space's page (shows the count first). Strings: `ar.task-privacy.json`.
- Feature switch `taskPrivacy` (OFF): makes a NEW task that somebody holds private by default.

## Switches
`taskPrivacy` — default OFF — OFF = a new task stays «المساحة كلها» unless the creator picks otherwise; the READ rule for private
tasks applies in every case (a switch never un-hides anything). The README's table said ON; see "Noticed".

## Decisions used
D-P2 — the recommended default («المعنيين بس» when somebody is assigned) is built behind `taskPrivacy`, OFF: turning it on would

plus the one-click). D-P4 — built as recommended (managers of the space, managers up the line, oversight), with the
partner-without-oversight exception above. All waiting («بانتظار المالك»).
