# F0 — The live line made reliable

## Definition of Done
- What must work (one commit per item, each with its failing test first):
  F0.1 a boot no longer replays 48 h of events before LISTEN is ready; a live event moves the listener's cursor; a dropped
  connection replays only the gap, once, in the background · F0.2 a stream that ends says `bye` (`evicted` or `signed_out`) and closes;
  the page goes to sign-in on `signed_out`, and on `evicted` does NOT reconnect (no ping-pong), polls every 60 s and says «الاتصال
  المباشر مفتوح بمكان تاني» · F0.3 the server sends a real `ping` event every 25 s; the page has a 60 s watchdog reset by any frame,
  ±30 % jitter on its retries, and really pauses after 60 s hidden · F0.4 the replay's kinds come from `REALTIME_KINDS` (one list) ·
  F0.5 a message is marked read only while the tab is visible and focused (marked once on return); a tab reports its visibility and a
  push is held back only for a person with a VISIBLE tab · F0.6 the chat list refetches once per burst (300 ms) and aborts the request
  it replaces · F0.7 a retry of a message already sent does not use the 30-a-minute quota · F0.8 messages are ordered and paged by
  `(createdAt, id)` · F0.9 `/api/health` shows `realtime: ok|down` and never changes the HTTP status because of it.
- Tests: `tests/db/realtime-listener-cursor.test.ts`, `tests/db/realtime-stream.test.ts` (ping, bye, eviction, signed-out, every kind),
  `tests/realtime-client-resilience.test.ts`, `tests/realtime-client-visibility.test.ts`, `tests/db/chat-viewing-push.test.ts`,
  `tests/chat-home-refresh.test.ts`, `tests/db/chat-send-idempotent-limit.test.ts`, `tests/db/chat-paging-ties.test.ts`,
  `tests/health-route.test.ts` (extended). Changed because they pinned a behaviour, not a rule: `tests/db/realtime-notify.test.ts`
  (its «replays what was missed» case now drops only the connection: `dropListenerConnectionForTests`),
  `tests/realtime-client-hook.test.ts` (the stream's address now carries the tab id).
- Edge cases that matter: an event that reaches the listener both live and by replay is delivered once (`firstSight`); the health route
  keeps its HTTP status (the database stays the only 503 reason) and its call brings the listener up after a deploy; presence (the green
  dot) is unchanged — only the push check moved to `isViewing`; a person with no stream but fresh presence is still «viewing».
- Blockers: CI red · an old test red · a secret exposed · a destructive migration (none: no schema change).
