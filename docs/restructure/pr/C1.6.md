# C1.6 + C1.7 — History paging, the unread landing, the jump, and the virtualized viewport (hooks for the C2 screen)

## Definition of Done
- What must work: (1) **Opening** a conversation: the server already sends `firstUnreadId` with every window, so opening is «fetch the newest window»; with no `firstUnreadId` (nothing unread, or no read mark) the person lands at the newest message; with it INSIDE the window they land on it; OUTSIDE the window one more request `around=firstUnreadId` and the around window is what is kept. A conversation already in the cache with nothing unread opens at once (no request); one with unread messages still asks (the cache cannot know which message is the first unread). (2) **Paging both ways**: within one screen of the top the page before the first message, within one screen of the bottom (when not at the newest) the page after the last; one request per direction at a time; a cursor is `(createdAt, id)` and ties on `createdAt` at a window boundary lose and repeat nothing in either direction. (3) **Jump** to a message (reply quote, pinned bar, search hit, `?m=`): `around`, then paging both ways, a return to the newest window, a highlight for 2 s. They are SIGNALS (`scroll`, `highlightId`): nothing here styles a bubble. (4) **Memory cap**: at most 10 windows (500 messages) per conversation in the cache; the windows far from the screen are dropped, the cut end says `hasOlder` / `hasNewer` true so the cursors page across the cut again. (5) **Viewport** (`@tanstack/react-virtual`, installed, unused until now): dynamic heights (`measureElement`), `overscan: 10`, `getItemKey` = the row key (the message id); older rows put above keep the visible message where it is; a picture reserves its box from the attachment's `width` / `height` and falls back to ONE fixed box when an older row has none; a voice row has a fixed height. (6) Today's owner-approved rules `onNewest()` / `isAtBottom()` of `conversation/client.ts` are imported, not copied, and their tests are untouched.

## What changed

- **`src/lib/chat/cache/index.ts`**: three export lines appended.
- **`src/lib/chat/history/`** (new, hooks and pure functions only): `landing.ts` (the rule: `landingRule`, `separatorBefore`), `open.ts` (`resolveOpening`: the opening, with `unreadHint` = the row's unread number, `messageId` = `?m=`, `current()` = is this run still the latest), `edges.ts` (`nextLoad`: within one screen of an edge, one request at a time), `jump.ts` (`jumpToMessage`, `backToNewest`, `JumpSignals` with `HIGHLIGHT_MS = 2000`), `use-conversation-history.ts` (`useConversationHistory(id, { around })`: ready, error / retry, messages, `hasOlder` / `hasNewer` / `atNewest`, `landing`, `unreadSeparatorBeforeId`, `scroll`, `highlightId`, `epoch`, `jumpTo`, `backToNewest`, `onViewport`, and the 10-window cap), `index.ts`.

- Tests and these docs: `README.md` and `C1-chat-engine.md` tick C1.6 and C1.7 (as hooks: the screen is C2.4). `docs/CODEMAP.md` is NOT regenerated here.

**How the viewport keeps the visible message in place.** BEFORE a render with new rows, the first visible MESSAGE row of the old layout is recorded (its key and its distance from the top of the view). In a layout effect of the new render, the scroll offset is set so that row is at the same distance; the rows that were only estimated and are measured later shift the scroll by what they changed (the virtualizer does that for rows above the fold). The same code handles a prepend and the cap dropping far windows above the screen.

**The landing.** `resolveOpening` puts the right window in the cache and answers where to land (`newest`, `unread`, `message`); `useConversationHistory` mounts the messages query only after that, so nothing is fetched twice and nothing shows in the wrong place first; then it raises the signal (`scroll`: «to the newest» or «to this message», aligned to the top for the unread line, centred for a jump; `highlightId` for 2 s on a jump only).
