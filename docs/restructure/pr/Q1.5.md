# Q1.5 — Problems become tickets («🎫 مشكلة»)

> Stacking note: the W1-tokens branch (`feat/system-tokens`) sits under this one only because it was built first; it has nothing to do with it.

## Definition of Done
- What must work: (1) «🎫 مشكلة» in a text message's menu opens a form (kind → order number first → «ما في رقم طلب؟ رقم الزبون» → a follow-up day for the kinds
  that ask for it → who) and makes a ticket where the message is, through the EXISTING doors (`createInstantTicket`, `createTicket`); the creator is the person
  who asked; the message keeps what it became; (2) who gets it: the person named → exactly ONE @-mentioned person → the department named → the kind's department
  → the kind's person → the asker's supervisor → the space's manager (never the owner by default) → else a clear refusal; (3) one problem = one ticket (a message
  with the order number or the customer's number of an OPEN ticket becomes a comment on it, 200 not 201); (4) a customer's number is found with the EXISTING
  phone pattern (exported from `src/server/ai/redact.ts`), normalised, kept ENCRYPTED with a keyed hash only for matching, masked in the title, the text and
  every comment through ONE helper, shown in full only through `ticketDetail` (the ticket's own readers), and wiped by a job 30 days after the ticket was
  resolved; (5) the chip under the message «🎫 T-45 · مفتوحة · مع فلانة», refreshed live (`ticket.changed`), and «✅ انحلّت: <ملاحظة>» as a reply to the message
  when the ticket is resolved (the note is masked); (6) rules: by topic (every new human message), by content (an order number AND a problem word), by hand; mode
  «اقترح» (a chip «بدك تعمليها تذكرة؟», one tap) or «تلقائي»; defaults «اقترح» for content and «تلقائي» for topic; OPEN topics only — a private conversation, a
  restricted topic or a team's topic gets a ticket by hand only; (7) waiting: the kind's hours (working hours of the company, Friday off by default) → a reminder
  to the holder, then the same time again → the department's lead, else the holder's manager, skipping anybody not ACTIVE, each step once; (8) the kinds, the
  rules and the working hours are edited with «ضبط التصعيد» (`escalation.configure`, checked nowhere before); (9) the switch `autoTickets`, OFF.
- Tests: `tests/customer-number.test.ts` (9), `tests/auto-rules.test.ts` (7), `tests/work-hours.test.ts` (5), `tests/auto-tickets-ui.test.ts` (3),
  `tests/db/problem-tickets.test.ts` (16), `tests/db/auto-tickets.test.ts` (8), `tests/db/ticket-escalation.test.ts` (5); must stay green: the ticket, chat and
  private-work tests, the whole suite.
- Edge cases that matter: a rule that cannot make its ticket never stops the message; «constructor» is no kind; a phone is never an order number and an order
  number is never a phone; a recording-kind is refused without a video on the message; a private source needs the confirmation.
- Blockers: CI red · an old test red · a secret exposed · a destructive migration (none).

## Switches
`autoTickets` — default OFF — OFF: no menu item, no chips, the door answers «not found», no rule runs, no reminder; tickets already made stay.

## Decisions used
D-Q1 (modes: «اقترح» for content, «تلقائي» for topic), D-Q8 (30 days) — both as the recommended defaults.

## Owner actions
Turn on `autoTickets`; set the kinds' departments or people, the rules and the working hours with «ضبط التصعيد» (there is no screen for them yet: the door
exists, `PUT /api/tickets/problem-settings`).

- «افتح بنظام الطلبات» on «مكرر» / «رقم غلط» / «حجز موعد» tickets (the orders system's page addresses are not in the contract yet) and the note on the order (`orders.note`).
- `followUpAt` is stored and asked for; its listing under «مواعيد اليوم» waits for the Today card.
- «/مشكلة» and «/مشرفتي» in the «/» menu, and «طلب إذن» as an approval form template.
- The people screen still hides `escalation.configure` (A1 shows it again).
- The reply «✅ انحلّت» is written as the person who resolved the ticket (the chat has no system author), and only when that person may post in the conversation.
- Three-character separators inside a number («079 - 123 - 4567») are not found by the existing phone pattern (reused as the spec says); the customer's number typed by hand inside a ticket comment is not masked; the screen of a ticket does not show the number yet (the data is in `ticketDetail`).
- The lock that makes two reports of one order one ticket is in this process (the app is one container); the unique guard of a database index was left out because a reopened ticket would collide with it.
- Saving the settings is a read-then-write of the company's settings: two owners saving at the same second can lose one save.
