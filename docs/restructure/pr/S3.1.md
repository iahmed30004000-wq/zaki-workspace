# S3.1 — ONE «الإعدادات» door (`settingsOneDoor`, OFF)

## Definition of Done
- What must work:
  1. **The switch.** `settingsOneDoor`, OFF by default, group «لوحات المالك والذكاء», `dependsOn: ["controlPanelV2"]`, name and hint in `ar.settings-one-door.json`. It is in force only together with `controlPanelV2` (`settingsOneDoorOf`): the company group draws the control panel's own section bodies and the row that opens the panel, so on its own the switch changes nothing (the owner cannot turn it on while the panel is off, and one already on stays harmless if the panel is turned off later).
  2. **One row.** With it ON the drawer, the rail, the side menu (old map) and the avatar menu show ONE row «الإعدادات» to `/settings/me`: no «إعداداتي», no «دليل زاكي», no «ترتيب» row, and the avatar menu loses «الدليل», «حسابي» and the gear (the guide stays inside «المساعدة», «حسابي» is the first section).
  3. **«ترتيب».** One small icon button (`data-nav-order-toggle`, Arabic name «ترتيب», no word on screen) in the drawer header (inside `data-shell="drawer-head"`), at the top of the rail, and in the side menu header; it calls the existing `onEditStart`. The in-drawer «تم» / «رجّع» stay. While the company's order is set the same place shows a locked button (`data-nav-order-locked`) that opens the ⚠️ + 🔧 note.
  4. **The frame.** `/settings/me` gets two groups: «إعداداتي» (the 11 sections, unchanged) and, for the people the control panel offers a section (`panelAccess` → `panelSectionsFor`, never a rank check of its own), «إعدادات الشركة»: «بيانات الشركة», «الميزات», «التكاملات», «المساحات» (the panel's own bodies, rendered from `/settings/me/[section]`, not rebuilt) and ONE row «لوحة التحكم» to `/owner`. An ADMIN gets integrations and spaces; a lead, a member and a guest get no group and the company sections answer 404; a partner follows what he holds.
  5. **«الإدارة» disappears** from the map (both maps) of an ADMIN or OWNER who holds at least one panel section (`oneDoorHidesAdmin`, `NavSubject.settingsOneDoor` + `NavSubject.panel`). A lead keeps it, a member keeps «الناس» (directory + «لوحتي»), a guest is untouched.
  6. **Old addresses.** `/settings` leads into the frame (`settingsDoorTarget`: the first company section the person may open, else the index; a guest still gets the refusal it had), `/profile` leads to `/settings/me/account` (it always did), every old admin address still redirects to its panel section (walk in the DB test).
  7. **OFF is today.** `navSubjectOf` writes the new keys only when true; every pinned test passes untouched (list below for the ones that had to learn the new key).
- Tests: `tests/settings-one-door.test.ts` (new, 41), `tests/db/settings-one-door.test.ts` (new, 15).
- Edge cases that matter: switch ON without the panel; an admin whose boxes were taken away; a partner with `integrations.manage` revoked; a guest typing a company address; a collapsed side menu; the company's order set; the reorder mode on.
- Blockers: CI red · an old test red · no schema, no migration.
