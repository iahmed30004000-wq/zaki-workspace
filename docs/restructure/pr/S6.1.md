# S6.1 — assistant voice without a GPU: a robust browser voice, the meeting agent fixed, text answers

No schema, no migration, no new switch, no new route. Everything runs without a graphics card.

## Definition of Done
- What must work:
  1. **Browser voice of the guide and «اتصل بالمساعد»** (`src/components/site-guide/voice.ts`, pure half in `src/lib/site-guide/voice-text.ts`): the Arabic voices are RANKED (ar-SA, then ar-JO, then ar-EG, then the Levant, then any `ar`; a natural / offline / Google voice beats a plain one, a «compact» one comes last; every other language is left out); the list is AWAITED (`voiceschanged`, a poll, and a 2 s timeout, because some browsers never announce it); the audio is UNLOCKED inside the tap (`unlockAudio()`: a silent utterance, called first in `startCall` and first in the `GUIDE_CALL_EVENT` listener, which runs in the same event as the tap); an answer is spoken in SENTENCE pieces (at most 160 characters each, a long sentence is broken at a comma or a space, nothing is cut: the old `slice(0, 600)` is gone); what is read out is CLEANED (markdown marks, links, paths, ids, phone-like digit runs, emoji, the guide's own `e12` references); a device with NO Arabic voice says so in Arabic once (`voiceStack.no_voice`) and the answer stays on the screen as text, instead of staying silent or reading Arabic in an English voice; a `cancel()` is followed by a short pause before the next piece, and a newer `speak` / `stopSpeaking` ends the pieces still to come; a watchdog moves on when an engine forgets to fire `end`. The exported API (`canListen`, `listenOnce`, `speak`, `stopSpeaking`, `canSpeak`) is unchanged; `assistant-call-button.tsx` still holds `new CustomEvent(GUIDE_CALL_EVENT)`.
  2. **Speed and volume**: a small panel inside the guide's window (`voice-settings.tsx`, opened by a sliders icon in the guide's header; «اتصل بالمساعد» runs through that window) with two sliders and «جرّب الصوت». Kept in `localStorage` (`zk-guide-voice`) on THIS device only, clamped (speed 0.6 to 1.6, volume 0.2 to 1), read again for every piece. `src/components/settings-me` and `control-panel` are untouched (S3.x own them).
  3. **Meeting agent, Levantine**: `MEETING_SYSTEM_PROMPT` asks for the Levantine the owner speaks (no «الفصحى», no «بدون لهجة عامية»); still short, spoken, no symbols, numbers in words, no tools (`tools: []` unchanged).
  4. **Meeting agent, the 25 s bug** (`voice-agent/logic.py`): the assistant is addressed only when NAMED (a whole word: `is_named` compares tokens, so «المساعدة», «تذكير», «ذكية», «مساعدك» never wake it; «وزاكي» still does) or in a short follow-up of 8 s (`FOLLOW_UP_SECONDS = 8.0`) from the SAME speaker it has just answered (`FollowUp`, keyed by the participant identity; measured to the moment the person stopped talking, not to the end of the slow recognition). What other people say in that window is not for it.
  5. **An addressed silence is not answered**: «[صمت]» or an empty model answer is silence even when somebody spoke TO the assistant (`REPEAT_REQUEST` and «لم أفهم جيدًا…» are gone from the site; the prompt now also says «[صمت]» when it did not understand); the agent speaks only what `logic.should_speak` lets through and never invents a sentence of its own.
  6. **Env knobs**: `voice-agent/docker-compose.yml` passes `EDGE_RATE`, `PIPER_LENGTH_SCALE`, `PIPER_NOISE_SCALE`, `PIPER_NOISE_W`, `PIPER_SENTENCE_SILENCE` (empty = the voice's own default), `STT_PROMPT`, `GEMINI_TTS_MODEL`, `VOICE_FILLER_TEXT` (and the existing ones). `.env.example` lists `VOICE_AGENT_URL`, `VOICE_AGENT_SECRET`, `MEETING_LLM_URL`, `MEETING_LLM_MODEL`, `MEETING_LLM_API_KEY` as commented NAMES with no value.
  7. **Text answers**: an answer the assistant speaks in a call is ALSO written as a line of the call's conversation, through the existing assistant-line shape (`kind` SYSTEM, `{k:"assistant", p:{text}}`, the same row «@المساعد» writes; no new table), authored by the owner's row (his assistant, his cost), carrying `first` on the conversation's first assistant line (the note about the model) and `local` when a model on his own server answered. Nothing is written for a call with no conversation (a meeting by link: skipped silently), a closed or archived conversation, a silence, or a conversation with a GUEST among its people (the voice stays in the room, a text line would stay in a history the guest can read). A failure to write never costs the spoken answer. The audit row gets `posted: true|false` (counters only, never the words).
  8. **Ring of authority kept**: the assistant is still owner-only, off by default (`assistantInMeetings`, `ownerAssistant`), the text goes through the existing redaction, no customer data goes to an external model, no tools.
