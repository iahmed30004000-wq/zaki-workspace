# C2.6 + C2.7 — The message menu, hover actions and shortcuts · the info panel (`chatLayoutV2`, OFF when merged)

## Definition of Done
- What must work: (1) **The registry stays the ONE source.** `MessageMenuId` and `messageMenuItems` learned five ids — `copyLink` «نسخ الرابط» (`/chat/<id>?m=<msg>`), `readText` «اقرأ النص», `transcribe` «حوّل الصوت لنص», `seen` «مين شاف» (a topic or a group, with today's reader list of THAT message), `ask` «اسألي مشرفتك» (the «🎫 مشكلة» door with the question kind `product_question`, when the company's `me.problemKinds` has it). They are **opt-in** (`context.surface === "v2"`): the old screen and the quick chat build their context without it and never receive an id they cannot run (a test sets every new flag and checks the old context offers none of them). With `surface: "v2"` the order is Telegram's (رد، نسخ، نسخ الرابط، ثبّت، حوّل، عدّل، احذف) and then ours (اعمل مهمة، اعمل تذكرة، «🎫 مشكلة»، اسألي مشرفتك، ذكّرني، ملاحظة، «لازم ينقرأ»، ترجم، اقرأ النص، حوّل الصوت لنص، مين شاف), in Telegram's words; `V2_MENU_ORDER` has a place for every id (a test fails for an id without one). «حدّد» (select) is C3b.5 and has no action, so its id is NOT added. (2) **The menu** (`components/chat/v2/menu/message-menu-v2.tsx`): the six quick reactions on top + «⌄» that opens a frimousse picker, then the registry's items; hover on the computer shows a reaction button, «↩» (only where the registry offers «رد») and «⋯»; a right click with the mouse opens the menu (the browser's own stays for selected text); a double click with the mouse replies (not on a link, a button or a player); the phone's long press opens the same list as a sheet with `LONG_PRESS_MS` reused; a delete asks first; nothing at all for a deleted message, a system line or the owner in silent oversight. A reaction goes through the existing react door (`commands.react`). (3) **Shortcuts**, ONE module `src/lib/chat/shortcuts.ts` (pure map + rules + the hook), mounted once from `chat-shell.tsx`, computer only: Alt+↑/↓ previous / next chat, Alt+Shift+↑/↓ previous / next UNREAD, Ctrl+1…9 the folders, Ctrl+F search in the open conversation (the list's search when the list has the focus), Esc closes the panel, then the search, then goes back to the list, Ctrl+Shift+? the sheet. Ctrl+0 and Ctrl+B/I/U/K are C3: not registered. On screen only «Ctrl» and «Esc» are Latin («ألت», «شيفت» in Arabic letters, arrows ↑ ↓); `tests/arabic-ui.test.ts`'s allow-list is NOT extended. (4) **The info panel** (`components/chat/v2/info/`, filling `pane/seams/info-host.tsx`): ONE body, `InfoPanel`, that does not import the pane's provider, so C2.8's phone route can mount it. 360 px column beside the conversation from 1024 px (portaled into a column the shell draws), an overlay sheet from the END side below it. Header with the big picture, title and line; «🔍 بحث» and the call button (only when `canPost` and `me.canCall !== false` and the calls switch is on). A private chat shows what the header carries, plus the job title and bio and «افتح الملف الشخصي» (`/u/<id>`) through the EXISTING `GET /api/users/<id>` (nothing when it refuses). A topic shows the space, who sees it («كل أعضاء المساحة (42)», «المقطع: …», «🔒 خاص — 3 أشخاص») and — P0.4 — a private row says so WITHOUT names unless the existing people door handed them over (an empty or missing list, or only the space's audience list, is no names); the moderators get «إعدادات الموضوع» (today's `TopicSettingsDialog`, unchanged), close / reopen and archive / bring back through the topics door.
- Tests (new): `chat-v2-menu-registry` (30: per id by permission — member, moderator, guest, owner joined, owner in silent oversight, deleted message, system line — the old screen never gets a new id, the order, the words, Q1 «🎫 مشكلة»), `chat-v2-menu-model` (20: the context, the six reactions, the link, the double click rule, the emoji data), `chat-v2-menu-render` (18: the bar, hover actions, the menu in Telegram's order by permission, the sheet, ONE render test each for «🎫 مشكلة» (`me.problemKinds`) and «اسألي مشرفتك», the menu inside a bubble), `chat-v2-menu-gestures` (22: the press of the picture's / voice note's own button, right click, double click, no double tap, the host's wiring, the picker), `chat-v2-shortcuts` (32: the map, the neighbour of the open chat, Esc, the rules, the bridge, the sheet's key names), `chat-v2-info-model` (16), `chat-v2-info-render` (22: a private chat, a topic, P0.4 with four ways of «no names», moderator buttons, no tabs, no bell, the frame, the places). 160 new tests.

## Independent review
There is no tool in this worker session to start a separate agent, so the review was the `code-review` skill (a forked, read-only reviewer that ran nothing) over the diff of the two commits (the first run looked at the wrong repository and found nothing to review; it was repeated on the diff file). 9 findings, each judged here.
- **Real, fixed (each with a test written first and seen red):** (1) «نسخ الرابط» did nothing, with no toast, when the browser has no clipboard (an insecure address, a webview): `copyText` now says it failed; (2) a message with several pictures: the press of «اقرأ النص» went to the first block even when it was already read — it goes to the first block that has no text on screen; (3) the keyboard's menu key (and a pen) did not open the menu, only a mouse did — anything but a finger's touch does; (4) Esc left the conversation while a popover or a tooltip was open — those are now «an overlay» too; (5) the menu context of every bubble was rebuilt on every draw — it is memoized; (6) the shell's new JSX block was not indented.
- **Answered without a change:** (a) `usePeople` runs before the `infoOpen` guard: it is the SAME cache entry the pane already asked for (one request per conversation, shared), so no second request is made; the comment now says so. (b) Ctrl+F and Ctrl+1…9 fire from inside a field: that is the spec (§8: search the open conversation from the composer too, folders by number); they have no text meaning, and they are the one case where the browser's own find / tab switch is replaced on the computer — listed for the owner's check. (c) `more()` closes the menu and opens the picker in one tick: the picker is a Radix dialog that takes the focus itself; a browser check (focus lands in the picker) is on the owner's list rather than guessing a delay. (d) «اقرأ النص» stays offered when every picture already shows its text: pressing it does nothing because the person already sees it; the registry cannot know the button's state.
