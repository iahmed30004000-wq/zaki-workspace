# P0.6 — The Android signing passwords leave the public repository

## Definition of Done
- What must work: `android/app/build.gradle` carries no password. It reads `ANDROID_KEYSTORE_PASSWORD` and
  `ANDROID_KEY_PASSWORD` from the environment; the Android workflow hands them over from the repository secrets; the fixed
  key is used only when the key file AND both passwords are there, otherwise the build uses the debug key and warns.
  `npm run scan:secrets` now fails on a Gradle file that writes a `storePassword` / `keyPassword` literal, so the form cannot
  come back.
- Tests: `tests/scan-secrets.test.ts` (extended, 7 cases: four literal forms and the Kotlin script are caught with
  file:line and never the value; an environment read passes; the Android project of THIS repository passes).
- Edge cases that matter: the generic rules missed the old line because the word it was made of reads like a placeholder, so
  the new rule flags ANY non-empty literal after those two names, in `*.gradle` and `*.gradle.kts`; a literal after `?:`
  (a fallback next to an environment read) is flagged too; an empty fallback passes.
- Blockers: CI red · an old test red · a secret exposed · a destructive migration (none).

## ⚠️ Owner actions FIRST — before this is merged
The old password stays readable in the public history, so it must be CHANGED, and the new ones must exist as repository
secrets before this lands (otherwise the next build is signed with the debug key and an installed phone refuses to update).
🔧 In this order:
1. Change BOTH passwords of the EXISTING key file with `keytool -storepasswd` and `keytool -keypasswd` (the same key, never a new one: phones keep updating).
2. Encode the changed key file again and replace the repository secret `ANDROID_KEYSTORE_B64`.
3. Add two repository secrets: `ANDROID_KEYSTORE_PASSWORD` and `ANDROID_KEY_PASSWORD` with the new values.
Nothing in this PR, its commits or the documents contains the old or the new value.

## What changed
- `scripts/scan-secrets.mjs`: rule `Signing password in a Gradle file` (`IS_GRADLE`, `GRADLE_SIGNING_LITERAL`).
- `android/app/build.gradle`: the passwords come from `System.getenv`; `zakiSigns` decides between the fixed key and the
  debug key and warns when the key file is there but a password is not.
- `.github/workflows/android.yml`: the build step passes the two secrets.
- `docs/ANDROID.md`: names the two new secrets.
