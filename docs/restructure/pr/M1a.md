## Independent review (read-only agent)
One read-only reviewer read the whole diff (no tests run). Real, each fixed:
- The first-private-chat ask called the browser's question outside a tap and used up its one try before the browser answered (Safari and Firefox refuse such a question): it is now asked only while `navigator.userActivation` is active, and the flag is written only after the decision to ask (test).
- The icon badge used the list's own number, which differs by design from the sidebar's (a topic never opened counts its whole history there): the icon could say 250 beside a menu that says 3. It now takes the sidebar's number once it has come and falls back to the cache's only before that (test).
- Stacked notification lines had no sender, so in a topic the line of a mention read as the line of whoever wrote last: each line now says who when the senders differ (test).
- The offline page's «online» handler sent the person to the home page and lost a deep link from a notification: it reloads the address that was asked for (test). The page is behind the sign-in in the middleware, so its precache is dropped when the session had ended: the worker now carries the same sentence in a small page of its own as the last resort (a test pins that the two agree).
- A DM follow-up's push tag was per message, so a client that honours the tag (the Android app's live line) would show one notification per message: the follow-ups now carry the conversation's page as their tag.
- A failed registration was never retried in the page's life: the flag is cleared on failure.
Answered without a change: a failed navigation that is not an offline one (a TLS error, a server that refuses the connection) shows the offline page too, which is the honest word for «the site cannot be reached»; two tabs on two builds after a deploy evict each other's shell cache, which costs a refetch and breaks nothing; two components call the (idempotent) registration, deliberately, because the `(app)` layout is not this package's; concurrent pushes for one conversation can lose a stacked line, rare and harmless.
