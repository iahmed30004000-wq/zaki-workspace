# C3b.1 — Text formatting: one pure parser to elements (`chatFormatting`, ON)

## Definition of Done
- What must work:
  1. **Stored as text, no schema.** `**bold**`, `__italic__`, `~~strike~~`, `` `code` ``, a fenced block of three back ticks, `||spoiler||`, lines starting with `> ` (quote), `[text](https://…)` and bare links (`https://`, `http://`, `mailto:`, `www.`), all inside `ChatMessage.body`. No migration, no new door, no new dependency.
  2. **ONE pure parser** `src/lib/chat/format/parse.ts` (blocks → inline tokens) and `render.tsx` (tokens → React elements). No raw-HTML API anywhere (a test greps every file of the formatter, the bubble body and the toolbar). `<script>`, `<img onerror>`, entities and `javascript:` stay plain text.
  3. **Links**: only `https:` / `http:` / `mailto:` (`links.ts`, `safeHref`); `rel="noopener noreferrer"` and `target="_blank"` outside; an in-app path (`/chat/…`, `/tasks/…` only, no `//`, no `..`, no backslash) is a `next/link` with no new tab. Refused and shown as typed: `javascript:`, `data:`, `vbscript:`, `file:`, `ftp:`, `//host`, an address with a user name or password (`https://google.com@evil.com`), a control or direction character in the address. A label that claims another site than the one it opens (`[paypal.com](https://evil.example)`, `[Visit www.bank.com](…)`) shows the REAL address; a sub-site of the named site, a file name (`invoice.pdf`) and plain words are honest labels and stay.
  4. **Strip everywhere text leaves**: `stripFormatting()` (built from the parser's own tokens) is used by the list row (`row-preview.ts`), the push body (`notify.ts`, also the rewrite on edit or delete), the search snippet (`search.ts`), and every text sent to a model: `buildChatPrompt` (the assistant, the digest and «لخّصلي», which read their rows through it) and the translate service. Stripping only: nothing new is sent, the privacy filter runs after it exactly as before, and a link's address does not travel at all (only its label).
  5. **Math**: `CHAT_SYSTEM_PROMPT`, the owner assistant's `SYSTEM_PROMPT` and the digest's calls carry `PLAIN_ANSWER_RULE` (plain text, no math markup). Leftover `\( … \)`, `\[ … \]`, `\frac{…}{…}`, `\text{…}`, `\sqrt{…}` are shown as plain characters without backslashes by the renderer (`math.ts`, no library); the assistant's stored answer and the digest answer are cleaned the same way (so the old screen shows them clean too). A backslash outside a formula (a Windows path) is never touched.
  6. **Composer**: a selection toolbar (bold, italic, strike, code, hidden, link; a press keeps the selection in the box) and Ctrl+B / I / U / K, Ctrl+Shift+X / M, decided by the PHYSICAL key (Arabic layout works), the command key of a Mac counts, never while an input method composes. Applying again undoes it; spaces at the ends of the selection stay outside the marker; several lines become a code block; a link puts the selection as the label and selects `https://` to type over. Ctrl+K inside the box is the link (the app's palette never sees it there).
  7. **Compose with Q1/C2**: mentions and order-number chips keep working inside bold words (one render test each); the Q1 bubble tests are untouched and green; a plain body renders the same `<p class="whitespace-pre-wrap text-sm leading-relaxed">` it always did.
  8. **Speed**: a 10 000-character body parses in under 5 ms for six shapes (mixed markup, unclosed markers, 10 000 «[», back ticks across lines, 5 000 «> », plain); best of seven runs after a warm-up.
  9. **Switch** `chatFormatting`, default ON (`features.ts`, the two Arabic lines, `tests/features.test.ts`). The new screen only: `message-item.tsx` (the old screen) is not touched.
- Tests (new, all green): `tests/chat-format-parse.test.ts` (50: every marker, nesting, unclosed markers, RTL/LTR, links and every refused scheme, label spoofing, injection, strip, math, speed, the model paths), `tests/chat-format-render.test.ts` (23: markup of every rule, link attributes, injection, no raw-HTML API in source, math, the previews, snippets, the push, spoilers), appended to `tests/chat-v2-bubble-render.test.ts` (7: formatting in the bubble, a mention and an order chip inside bold, a code span is not a chip, plain markup unchanged, `formatting={false}`) and `tests/chat-v2-composer-render.test.ts` (12: keys, `applyFormat`, parser round trip, toolbar, surface, key-order pin), `tests/features.test.ts` (+1).
- Run and green besides them: every `tests/chat-*.test.ts`, `ai-*`, `digest`, `message-translate`, `features`, `arabic-ui`, `no-hardcoded-colors`, `encoding-hygiene`, `repo-hygiene`, `ui-font-floor`, `ui-primitives-v2` (98 files, 1529 tests); `tsc --noEmit` and eslint clean on every file touched.
- Edge cases that matter: `2 ** 3 ** 4`, `a || b`, `****` are not markers; crossing markers never cross; a marker next to a space is plain; `**https://a.com**` links without the stars; `Foo_(bar)` keeps its bracket; a code span, a fence and an address are never formatted inside; markers inside a link's address are not markers; a spoiler inside a link label stays literal; a preview cut by the server inside a spoiler (`partial`) hides the rest of the line.
- Blockers: CI red · an old test red · customer data to an external model (none: stripping only) · a destructive migration (none: no schema).

## Switches
`chatFormatting` (ON). Off: the body is drawn as plain text and the composer draws no toolbar and answers no shortcut; what people wrote is untouched. See «Not done here» for the wiring.

## Decisions used
D-C1 (the old screen stays untouched). The privacy rule «no customer data to an external model» is unchanged.
- **Decision for the lead: Ctrl+U.** The spec lists Ctrl+U but has no underline marker (`__` is italic). U is bound to the spoiler (`||`); the toolbar shows it as «إخفاء النص». If it should stay unbound, delete one line in `formatActionOf`.
- A spoiler is hidden («•••») in previews, push and snippets; a spoiler's words are KEPT for the model paths (the people who ask can read them in the conversation).
- Previews and the model paths strip always, whatever the switch says (the markers are never useful there).

## Owner actions
- 🔧 Needs a real browser (not measured here): the selection toolbar's position over the box on the phone; Ctrl+B / I / U / K and Ctrl+Shift+X / M in Chrome, Edge and Firefox on Windows (Ctrl+Shift+M may be taken by the browser in some of them: the toolbar is the fallback); tapping a spoiler; a long link wrapping inside a bubble; a code block scrolling sideways.
- ⚠️ A link written by a person opens in a new tab: the reader sees the address in the browser's own bar, and a label that names another site shows the real address instead. 🔧 The label check knows domains by shape (letters, dots, a 2 to 24 letter ending) and a short list of file endings.

## Not done here (recorded)
- **The `chatFormatting` switch does not reach the two components yet** (files of other packages): add `chatFormatting?: boolean` to `ConversationHeaderDto` (`src/server/chat/dto.ts`), set it in `topics.ts` next to `chatOutbox` (`isFeatureOn(ctx.orgId, "chatFormatting")`), carry it through `bubbleFactsOf` and pass `formatting={facts.formatting}` in `message-bubble.tsx` line 150, and pass `formatting={header.chatFormatting !== false}` to `ComposerSurface` through `composer-host.tsx` / `chat-composer-v2.tsx`. Until then the components default to ON and the OFF behaviour is proven only on the components (`formatting={false}` tests).
- **The assistant's line** (`message/assistant-line.tsx`) still draws its text raw; the answer is stored math-clean (this package), so the line shows no math markup, but it does not draw bold or links. Passing the text to `FormattedText` there is a one-line change in a file of another package.
- **Reply-quote and pinned-message previews** (`previewOf` in `server/chat/redact.ts`, `topics.ts`, the reply block) still carry the raw body: a quoted `||secret||` shows its markers and words there. They should call `stripFormatting(…, { math: true, partial: true })` (client side in the reply block is enough).
- **`messages.ts` cuts the push preview at 140 characters before `notify.ts`**; stripping copes with a cut (`partial`) but a link cut inside its address can show half of it only if it is not a `[label](…)`. Passing the whole body would be cleaner.
- **`search-embeddings.ts`** (semantic search, OFF by default) sends redacted chat text to the embeddings service without stripping the markers (it only embeds words with a few stars around them; no new data). Not in this package's paths.
- **Search still matches the raw body in the database**: a phrase that crosses a marker (`**hello** world`) is not found by «hello world», and the snippet of a hit inside a spoiler shows «•••».
- **Underline**, **headings**, **lists**, **backslash escapes**, **custom emoji**: not in the spec, not built. A spoiler shown once stays shown (no re-hide). Links in the composer are not previewed (C3b.2).
- No engine or DOM test of the keyboard in a browser (the repo's unit tests run in Node): the pure functions are tested, the surface is pinned by a source test (formatting keys are asked before the engine's, `stopPropagation`, the switch).
- `docs/CODEMAP.md` is NOT regenerated or committed (the integrator does it): `tests/codemap.test.ts` is red until then.
- The full unit suite, the database tests and `next build` were not run (shared `node_modules`, no server file with a query changed).

## Independent review
A read-only review of the diff (`/code-review`, high; it ran no test) found nine things. Taken, each with a failing test first: (1) a hidden spoiler was hidden only by inherited `text-transparent`, so a link or a chip inside kept its colour and stayed focusable: now the whole subtree is `invisible`, and a shown spoiler is plain words with no button around it; (2) the label check missed a bare domain or a sentence containing one (`[paypal.com](https://evil.example)`): now every address-shaped word of the label must name the target's site; (3) a spoiler inside a link label put a button inside an anchor: not formed there; (4) the push and list previews are cut by the server at 140 characters, so a spoiler could lose its closing marker and show its words: `partial` closes it; (5) `SYMBOLS[name]` found `constructor` and `toString` on every object: own names only; (6) the lazy math scan was quadratic on a long run of `\(`: one pass, each closer looked up once, a formula capped at 600 characters. Not taken here (not this package's files, listed above): the switch's wiring, the reply-quote and pinned previews, and search matching the raw body. The preview strip ignoring the switch is a decision (above).
