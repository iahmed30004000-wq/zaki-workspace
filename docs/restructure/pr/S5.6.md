# S5.6 — Emoji that react: jumbo + pop + tap, chip burst, «مين تفاعل», Zaki emoji as reactions, task stickers in the picker (switches `zakiEmojis` / `chatLayoutV2`, existing; no new switch, no schema, no migration)

## Definition of Done
- What must work:
  1. **A message of ONE to THREE emojis** (unicode, Zaki `:zaki_id:`, or both, spaces allowed; no file, card or poll with it) is drawn BIG (`JumboEmoji`: the fewer, the bigger). It **pops** only when it has just ARRIVED (the bubble's own `isFreshArrival`, decided once at mount: a re-render, opening a chat or scrolling up never plays it). A **tap replays a short wiggle** (decoration only: nothing is sent, the bubble's long press and double tap still work). Words, four emojis, `**😀**`, `©` and an unknown code are NOT jumbo.
  2. **Reaction chips burst** when a reaction is added (a chip that is new or whose count grew; never on the first draw, never on a removal).
  3. **«مين تفاعل»**: a long press (phone), the right button or the keyboard's menu key on a chip opens a sheet: a tab «الكل» (each person once, with their emojis) and a tab per chip with its count; rows = picture + name («أنت» on mine); «و N غيرهم» for what the server could not name. A plain tap still toggles my reaction (Telegram's way); while the owner only reads (no right to react) a tap on a chip opens the list instead of doing nothing.
  4. **The DTO carries the names**: `ReactionDto.by?: { id, name, avatar?, me? }[]` (src/server/chat/dto.ts), built in `redact.ts` from the message rows' own join (`messageInclude`, one batched relation read, reactions ordered oldest first; no query per message). Rules: a GUEST sees only himself (and gets no picture address); the ✅ receipt of «لازم ينقرأ» names its people to the author, the moderators and the owner only (everybody else: the count and themself); a restricted topic is readable by its members only, so its names never leave it (an outsider's read is a 404 before any name); a deleted message carries no reactions (the owner's existing exception unchanged); at most `REACTORS_CAP` = 50 names per chip (the count stays the truth).
  5. **Zaki emoji as reactions**: the server's `isSingleEmoji` (messages.ts) now accepts exactly ONE real emoji (pictograph with variation selector/skin tone, flag, keycap, joined family; ≤ 16 characters, no spaces) or ONE known code of the pack (`isZakiCode`: allow-list from `zaki-emoji.ts`, the 32 chat emojis AND the 16 task stickers). Any other text (`hello`, `<b>x</b>`, an unknown `:zaki_nothing:`, a code with words around it, a doubled code, upper case) is refused with `chat.e.bad_reaction`. `reactSchema` max grew 16 -> 32 (a code is longer). A Zaki code is refused with `chat.e.zaki_reaction_off` when the company switch `zakiEmojis` is off. The chip draws the picture (name for a screen reader).
  6. **Task stickers (16) in the picker, under their own tab** «حالات المهام»: in the composer's emoji panel (beside «ذكي», same switch) and in the reaction picker (`EmojiPickerDialog` has tabs «إيموجي · ذكي · حالات المهام», `zaki={false}` hides them). Picker only: NOTHING in the work pages uses them.
  7. **The unsent bubble draws Zaki emoji** as pictures (and a lone one big), never `:zaki_id:`.
  8. **Notifications say the Arabic name**: `previewText` (bell + push body), `previewOf` (list rows, pinned bar) and the reply quote show `(احتفال)` instead of `:zaki_party:`. The hint of the `zakiEmojis` switch (ar.features.json) no longer promises the raw code in notifications.
  9. **Pure CSS, no assets**: keyframes in the NEW `src/components/chat/v2/bubble/emoji-alive.css` (`zk-emoji-pop`, `zk-emoji-wiggle`, `zk-chip-burst`, `zk-chip-ring`); every one is switched off under `prefers-reduced-motion` and the emoji / chip stays fully visible without it. `globals.css` is untouched. No Lottie, no Telegram artwork, no new binary.
- Tests (written first): `tests/chat-emoji-alive.test.ts` (new, 36), `tests/db/chat-reactors.test.ts` (new, 10).
- Existing tests updated DELIBERATELY: `tests/chat-v2-bubble-render.test.ts` (1 test: a chip while the owner only reads is now `aria-disabled` and NOT `disabled`, because a press there opens the who-reacted list); `tests/chat-v2-motion-model.test.ts` (1 test ADDED: the emoji animations live in their own CSS file and stop under reduced motion). Green and unchanged: `zaki-emoji.test.ts`, `zaki-emoji-render.test.ts`, `chat-modern-bubble.test.ts`, `chat-v2-menu-render.test.ts`, `chat-v2-menu-model.test.ts`, `chat-cache-reducers.test.ts`, `chat-optimistic-pending.test.ts`, `chat-v2-composer-render.test.ts`, `features.test.ts`.
- Edge cases that matter: a flag, a keycap, a skin tone and a family are ONE emoji each; the ✅ is still reserved; 12 distinct emojis per message is still the cap (a Zaki code counts as one); a guest who did not react gets no names at all; a message whose reactions were stored before this change (older cache) shows «و N غيرهم» instead of names.

## Not done here (recorded: files of other packages, or a decision)
- **Nothing was measured in a browser** (no dev server): the pop / wiggle / burst timings, the long press on a chip on a real phone (the swallow of the click after it), the sheet on top of the chat and the tab bar of the picker (now scrolls sideways when 11 tabs do not fit) are covered by markup, source and CSS tests only. Please look at them on a phone and on a computer.
- **Interpretation of «long-press or tap»**: a tap on a chip still TOGGLES my reaction (as before and as Telegram does); the list opens on a long press, the right button / menu key, and on a tap where the person may not react (the owner reading silently). If you want a tap to open the list for everybody, change `Chip.onClick` in `bubble-parts.tsx`.
- **Quick reactions / double tap** (`quick-reactions.ts`, `prefs.ts`) still accept unicode emojis only: a Zaki emoji is picked from the picker. `prefs.ts` is another package's file.
- The reaction picker shows the Zaki tabs even while `zakiEmojis` is off (it cannot read the switch: `message-menu-v2.tsx`, which would pass it, is outside this package); a press then gets the Arabic refusal from the server. `EmojiPickerDialog` already takes `zaki={false}`.
- The bubble still keeps its background behind a jumbo emoji (Telegram drops it): `bubble-model.ts` is in `pane/`, outside this package.
- «مين تفاعل» is not shown in the old (non-v2) chat screen: it keeps its own chips, untouched.
- The names of the people behind a chip travel with every message payload (cap 50 per chip): a message with many reactions is a little larger.
- **Not run here (shared `node_modules`)**: the full unit and database suites, `npm run build`, `scan:secrets`.
- Review: no subagent could be spawned; the review was my own read of the diff (hook order in `ReactionChips`/`ReactorsSheet`, the portal-event leak into the bubble's long press — the sheet is drawn outside the article and the chip stops its own pointer-down —, the guest / receipt / restricted-topic cases of `groupReactions`, CRLF state of touched files).
