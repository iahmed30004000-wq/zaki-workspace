# C3a.3 — «الرسائل المحفوظة»: a private chat with oneself (`savedMessages`, ON)

## Definition of Done
- What must work: (1) **No schema change, no migration.** A saved chat is a DM: `kind = DM`, `dmKey = "<me>|<me>"` (NO space suffix: it is the person's, one per company, listed in every space they are in), `spaceId` null, ONE `ConversationMember`, stored with the title «الرسائل المحفوظة» (so the header, the old screens and the quick chat name it without any new code). (2) **`openSavedMessages(ctx)`** in `src/server/chat/dm.ts`: create-or-get, idempotent on the existing unique `(orgId, dmKey)`: two tabs at once end with ONE conversation and ONE row (the loser of the race catches the unique violation and reads the winner's row; nobody gets an error); a lost member row is put back; a guest gets 403 (`chat.guest_forbidden`), a suspended person 404. A new saved chat is pinned for the person through C3a.1's own column (`ConversationMember.pinnedAt`, only while they have fewer than `PINS_MAX` pins); a person may unpin it and opening it again never pins it again. One event for the person alone (`conversation.changed` with `targetUserId`, ids only) so their other tabs get the row through the sync feed. (3) **The door:** `POST /api/chat/dm` `{ saved: true }` (201 the first time, 200 after); `{ userId }` works as before; anything else is a 422; the switch off is a 404. (4) **The privacy core, `loadConversationFacts`:** for a self-DM `dmOtherActive` is the VIEWER being ACTIVE and not a guest. Nothing else is loosened: another viewer still lands in the old branch (the pair's one person is "the other"), so an outsider, a partner without `archive.view`, an org admin, a space admin, a team member and a guest read nothing; the owner (silent oversight) reads it under the SAME rule as every DM and may not write in it (D-C3, default «آه»). (5) **The list, both shapes of D-N2:** `chatOneList` on (`GET /api/chat/list`) and off (`?spaceId`) both show the row: `scopeSql` lets the viewer's own saved key through in a space's list. The row is titled from the dictionary (never my own name), has no space chip, no peer picture, `peerId` = me, and a last message with NO tick status. The company's switch is read inside the list's one query (`savedOnSql`, like C3a.1's), so the sync feed still reads no settings; off, the row is in nobody's list or feed and nothing is deleted. `GET /api/chat/list` also answers `saved` (the switch is on and the viewer is not a guest). (6) **The screen:** the row has a bookmark for a picture and no typing line; the list column draws ONE pinned entry «المحفوظة» on top while the switch is on and the chat does not exist yet (it opens the door and goes there); the message menu has «حوّل للمحفوظة» right after «حوّل» (registry id `saved`, `surface: "v2"` only: the old screen and the quick chat never receive an id they cannot run; not on a poll, not inside the saved chat itself; it runs INSIDE `MessageMenuV2`: the dm door, then today's forward door); Ctrl+0 opens the chat (`savedShortcutOf`, by the physical key, with a dialog or menu open it is left alone); the info panel of the chat has a bookmark, no call button, no profile, and ONE line: «⚠️ المحفوظة مش سرية عن المالك…» (shown unless the server says nobody else holds oversight). (7) **The switch `savedMessages`**, default ON.
- Tests: `tests/db/saved-messages.test.ts` (27: the key and the row, idempotence, five tabs at once, a lost row, guest / suspended, the pin limit, the old pair DM untouched, the policy for the person / an outsider / a guest / a suspended person / the owner / a partner without the eye, the door and its 403 / 422 / 404, the list in both shapes and for nobody else, no ticks, unpin, the sync feed, the switch off and back, `saved` in the list answer, the old DM list never shows it, forwarding into it and nobody else forwarding into it, the header), `tests/db/privacy-matrix.test.ts` (+2: the C3a.3 row — the door, header, messages and policy of a saved chat agree with the `dm` row over all nine personas and nobody but the person lists it or writes in it; every persona makes exactly one of their own, a guest cannot), `tests/chat-v2-menu-registry.test.ts` (+19: the `saved` id per person and per surface, the new order, `isSavedRow` / `isSavedHeader` / `savedFlagsOf`, the open menu with and without a cache, `keepInSaved`, the row, the list column's entry, Ctrl+0, `openSavedChat`), `tests/features.test.ts` (+1).

- Blockers: CI red · an old test red · a secret exposed · a destructive migration (none: no schema change).

The tests were written first. `tests/db/saved-messages.test.ts` imports `openSavedMessages` and `savedKeyOf` from `@/server/chat/dm`, which did not exist (the file could not even load); the registry, features and matrix blocks assert ids, keys and switches that were not there. They were not run red one by one: the first run after the code was all green except four test mistakes (a `.status` on a thrown error, and a claim that a guest with a row FORCED into somebody else's saved chat cannot read it, which is today's rule for every DM: a row is the audience, so that claim was dropped).
